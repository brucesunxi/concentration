# 国家、年龄、语言与平台准入：v0.36 工程契约

本契约服务全球家庭产品的逐市场开放。**当前服务仍是本地开发版，不能招募真实家庭或商业开放。** `APP_MODE=production` 继续拒绝启动。国家法规判断、签署和真实家庭试用批准属于产品、法务与安全团队，不由代码自动完成。

## 现在已接通的行为

- 家庭注册接受 `residenceCountry`（两个大写字母）和 `registrationPlatform`。本地 Web 与原生客户端只提交虚构测试地区 `ZZ`；历史家庭迁移时标为 `ZZ`。`ZZ` 不得写入真实市场清单。
- 服务端在**注册、创建孩子档案、开始每次新练习**时查相同矩阵。未匹配的组合返回 `MARKET_NOT_OPEN`。原生注册必须区分 iOS 与 Android；Web 注册不得伪装原生平台。
- 规则是一行一个「居住国家 × 年龄档 × 内容语言 × 平台 × 家庭练习用途」组合，含版本、监护告知文本版本及摘要，以及产品、法务、安全三方独立审批记录引用。空清单默认全部关闭，重复项、不完整引用和相同地区/年龄/语言下冲突的告知文本拒绝加载。
- 老家庭因缺少可信居住国家信息继续留在本地开发地区；不能根据界面语言、时区或 IP 自动推断其市场身份。
- 规则撤回后，新练习不再发放；旧会话的联网状态检查与上传处理见下文。断网设备的即时通知和紧急召回仍需另行设计。

v0.35 为每次新练习保存准入矩阵身份：版本号与排序后规则内容（包括审批引用）的 SHA-256 摘要。服务端在状态查询、上传、结算和恢复时重新比对身份及当前规则；即便同一版本号下改动了审批引用，旧会话也返回 `MARKET_SCOPE_CHANGED`。家长恢复页面保留旧记录与导出入口，禁止再次点击恢复。既有本地会话迁移为 `local-development`，不会因此丢失。

v0.36 将告知文本版本与摘要也纳入该身份；批准矩阵下的采集还必须有未过期、未撤回、与当前身份和孩子属性一致的[监护核验记录](GUARDIAN-CONSENT.md)。本地预览勾选不能满足这一门槛。

断网设备在联网前无法收到撤回；签发过的离线授权在本机可持续到其原有期限。这不是即时远程停用。生产版本还需发布清单分发、客户端撤回信号、通知与应急流程。准入矩阵变更后，旧会话必须由家长在恢复入口处理；系统保守保留原额度，不悄悄给新会话释放额度。

`apps/api/release-scope.ts` 提供纯规则评估和本地开发适配器。`service(...)` 的第五个参数可以注入批准矩阵，集成测试覆盖准入与拒绝；当前运行入口只使用 `ZZ` 开发适配器。审批引用是可追溯 ID，**不是密码学签名，也不能证明签署者真实身份**。部署读取、审批工作流和发布审计尚未实现，因此不能把这项工程交付标为 D01 完成。

## 团队下一步执行

1. 产品负责人建立首发组合表，逐行指定经营主体、国家、年龄档、语言、平台、用途、销售渠道和责任人；不使用「全球全部开放」一行代替。
2. 法务与安全分别核对每行的儿童资料、家长身份与同意、区域存储、内容分级、支付/退款、支持和事故处理；留下独立审批证据。
3. 平台团队实现只读、版本化的部署清单及签署验证，使用发布流水线注入服务端，并使旧版本无法回滚覆盖新拒绝规则；在生产启动门槛通过后才启用。
4. 家庭端正式注册须采集声明的居住国家，并结合商店/付款地区及运营审核处理不一致情况；不能只相信用户可修改的字段。迁移旧家庭需家长确认，不能把 `ZZ` 自动换成国家。
5. QA 对每个获批组合以及相邻未批组合执行注册、创建档案、开始练习、规则撤回、离线授权和内容召回测试。保存清单版本与结果；确认家长文案与客服路径。

当前完整试用门槛仍见 [下一阶段交接](NEXT-DELIVERY.md) 与 [执行计划](DELIVERY-PLAN.md)。
