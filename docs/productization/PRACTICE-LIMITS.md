# 练习与休息：家庭安排与每日额度

v0.21 · 2026-10-01。家庭 Web 和原生入口已接通，API/schema 为 0.21.0/19，原生壳仍为 0.2.0。此功能让家长缩短后续练习或安排休息，并让孩子看见同一安排。它计量任务有效时间，不计量设备总屏幕时间；这些开发上限尚未经过适龄使用验证。

## 1. 家庭如何使用

在「练习与休息」选择孩子，查看今天安排和明确的后续生效日期。家长选择上限、确认已理解日期并会与孩子商量，保存后显示服务端确认结果。孩子仅能查看自己安排，可随时自行结束练习，也可转到生活小目标。

| 年龄段 | 默认/最高有效任务时间 | 家长可选 |
|---|---|---|
| 6–8 | 每日 8 分钟 | 暂停，或 1–8 分钟 |
| 9–11 | 每日 10 分钟 | 暂停，或 1–10 分钟 |
| 12–14 | 每日 12 分钟 | 暂停，或 1–12 分钟 |
| 15–17 | 每日 12 分钟 | 暂停，或 1–12 分钟 |

上限不表示应该用满。说明、暂停、反馈及其他页面停留不计入有效任务时间；本功能不构成治疗剂量或屏幕使用建议。v0.22 已增加 [单次总期限与休息询问](PRACTICE-WINDOW.md)，跨会话连续使用与疲劳策略另行建设。

**所有修改从下一个家庭日生效**，包括减少、恢复上限、暂停和重新开放。日期按家庭时区计算，不能用固定 24 小时替代，夏令时日可能不同。例：10 月 1 日把 8 分钟调成 3 分钟，今天仍按 8 分钟，10 月 2 日及以后按 3 分钟，直到再次修改。

这是已有离线授权的约束：今天已准备的任务可能正在另一台断网设备运行，新设置不会撤销或改写原签名授权。该授权本身在家庭当天结束前到期。当前设置不是远程即时锁屏；今天需要休息时可由孩子直接结束。不用重新登录、重开任务或换设备来增加当天时间。

家长可在生效前重选另一个值；选回今天值会取消待生效安排。停止采集后安排只读，不能通过修改设置重新开放采集。删除档案遵循现有家长资料流程。

## 2. 额度如何计算

按 `child_id + budget_day` 汇总所有会话。`budget_day` 是创建时的家庭日期，补传结算不将昨天的使用移动到今天。

```text
当日有效上限 = 已到生效日期的设置，否则当前设置，否则分龄默认
已确认用时 = 有结果会话的 used_ms 总和
预留时间 = 未有结果的活动会话 budget_ms + 未有结果的关闭会话 used_ms
可再安排 = max(0, 当日有效上限 − 已确认用时 − 预留时间)
```

新会话先预留全部可用时间，完整结果确认后按有效用时结算；换设备、授权到期及召回仍沿用原有保守结算规则。尚未完整确认的旧记录不提前退还额度。余量少于 5 秒时不创建新练习，设置为 0 时返回暂停状态。恢复页和开始接口使用同一计算函数，避免两个入口显示不同余额。

页面的数字是请求时快照，可主动刷新。`status=reserved` 优先说明存在未结清记录，不单独表示可用量一定为零；是否能创建由实际 `availableMs` 和原有活动会话规则决定。页面显示安排、原有签名续练与结果补传分别处理，不会因看到暂停文案而丢弃待同步记录。

v0.46 两端页面最长每 5 分钟重新读取一次，临近服务端所标家庭午夜时提前读取；Web 重新可见或获得焦点、原生 App 回到前台时也重新确认。计时使用响应中的 `generatedAt` 和家庭时区，包含夏令时与非整点时区，不按设备日期猜测家庭日。读取不会写入任何安排。同一安排下只更新用时数字，保留本页未提交的选择；家庭日期、分龄或设置改变时，旧确认勾选立即失效并重新展示当前安排。短暂网络/服务器故障保留草稿，标出“上次确认的安排”并阻止保存，约 60 秒后重试；身份失效或响应作用域不匹配会清除画面。草稿只在页面内存中，离开页面或原生隐私遮罩导致卸载时不保证恢复。详见[刷新验收](qa/practice-plan-refresh-v0.46-qa.md)。

## 3. 接口与权限

| 操作 | 请求 | 条件与结果 |
|---|---|---|
| 读取 | `GET /api/children/:id/practice-limits` | 家长读取本家庭孩子；孩子只读自身。无写入，响应 `no-store` |
| 修改 | `PATCH /api/children/:id/practice-limits` | 最近 10 分钟内验证的家长；有效采集档案；版本及日期匹配 |

修改示例：先读取 `settingsVersion` 和 `nextDay`，再发送以下数据。示例日期仅供说明，客户端必须使用实际读到的日期。

```http
If-Match: "3"
Content-Type: application/json

{"minutes":3,"effectiveDay":"2026-10-02","acknowledged":true}
```

字段严格解析，分钟为整数 0–12，并再次检查分龄上限。Web 继续要求同源、Cookie 和 CSRF；原生使用独立 Bearer，不能相互借用传输身份。服务在同一家庭事务中重新验证身份、锁定档案、比较版本、更新安排并返回新快照。

| 返回码 | 含义与客户端行为 |
|---|---|
| 428 `VERSION_REQUIRED` | 未提供版本；重新读取 |
| 400 `INVALID_VERSION` | 版本格式不合约 |
| 409 `LIMIT_VERSION_CONFLICT` | 另一页面或设备已修改；清除旧表单，重新读取后确认 |
| 409 `LIMIT_DAY_CHANGED` | 表单跨过家庭日边界；重新查看实际生效日期 |
| 400 `LIMIT_ABOVE_AGE_MAXIMUM` | 超过该年龄的开发上限 |
| 403 `REAUTH_REQUIRED` | 家长验证过期；重新验证再读取 |
| 403 `CONSENT_REVOKED` | 采集已停止，不允许修改 |
| 409 `PRACTICE_PAUSED` | 开始新练习时，今天安排为暂停 |
| 409 `DAILY_LIMIT` | 开始新练习时，余量不足 5 秒 |

响应契约 `practice-limits-1` 包含孩子/年龄、设置版本、角色能力、采集状态、家庭日期/时区/下一日、当前上限/最高值/待生效值、确认/预留/可用毫秒和状态。兄弟姐妹及其他家庭拒绝访问。

本接口没有独立幂等命令表。重复提交使用同一旧版本会冲突，不能覆盖新安排；若网络回执不确定，客户端不声称保存成功，也不自动换版本重试，要求先读取结果。按钮忙碌时防重复提交，切换档案或退出后忽略晚到响应。

## 4. 数据和版本

迁移 19 在 `children` 增加 `daily_limit_minutes`、`next_daily_limit_minutes`、`daily_limit_effective_day`、`daily_limit_version`、`daily_limit_updated_at`。空值沿用原分龄默认；数据库检查当前/待生效范围、成对字段和日期格式。是否为正确下一家庭日由服务检查。

每个新会话保存 `daily_limit_snapshot`：规则版本、设置版本、家庭日、有效分钟。原签名授权继续保存实际 `maxActiveMs`；历史会话允许快照为空，不能伪造原来的家长设置。导出包含当前安排和逐会话快照；当前安排去掉重复的 `generatedAt`，导出仍用顶层 `exportedAt` 标记生成时间。尚无独立的每次设置变更历史，不能据此提供完整操作审计。

实现入口：`apps/api/practice-limits.ts` 为迁移/计算；`service.ts` 为权限/事务；共享契约、客户端与中英文文案位于 `packages/contracts`、`packages/session-runtime`。Web 懒加载独立页面，原生复用请求状态机和文案，没有新增原生依赖。

### 升级步骤

1. 保留同批数据库和签名目录备份，停止连接该库的全部旧版 API。旧服务不会执行新上限，不能滚动混用。
2. 独立 PostgreSQL 用迁移身份执行 `npm run db:prepare`，确认 schema 19；本地 PGlite 在启动时迁移。
3. 启动 v0.21 服务并检查健康与只读安排。运行角色要求版本恰为 19，拒绝旧版/未知未来版。
4. 部署已验证 Web 文件；离线网页下载新版后，关闭本站全部旧标签页再打开。已有签名练习按原授权处理。
5. 回退须恢复兼容的应用、数据库和签名目录；不能删除迁移记录或让旧 API 继续处理新设置。
