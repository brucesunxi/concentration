## 2. 可重复的图片打包

```sh
npm ci
npm run visuals:build
npm run visuals:check
npm run visuals:proof
npm run build
npm run content:audit
```

`visuals:build` 使用锁定的 Sharp 0.35.4；它只从已保存原始图缩放和编码，不重新生成创意画面。任务图集使用保留透明通道的 PNG；网页装饰图使用 WebP，原生装饰图使用 PNG。尺寸缩放保留完整画布，不自动裁切图格；移除交付文件的多余元数据。[Sharp 尺寸规则](https://sharp.pixelplumbing.com/api-resize/)、[Sharp 编码规则](https://sharp.pixelplumbing.com/api-output/)

`visuals:check` 核对原始图/交付图摘要、尺寸、透明通道、图格非空与边缘至少 2 像素的裁切安全距离、每文件和网页图片预算，并校验保留历史图的原始摘要。它不能判断动物是否画对、孩子能否辨认、颜色是否跨文化合适，也不能代替原生解码和无障碍验收。

所有任务素材仍通过原有发布签名、SHA-256、字节数、语言/年龄/协议绑定和预先解码检查。图像更精细不意味着任务已通过科学或专业内容审核；当前所有内容包仍为 unreviewed。

## 3. 更新与历史恢复

新会话下发 **0.7.2-preview** 内容。不能把新图写到旧内容 hash 对应的地址，也不能合并新旧图条件下的成绩。当前难度规则按完整条件寻找记录，因此新内容条件会从基础难度开始；这是现有保守规则的结果，后续可由方法负责人设计并验证迁移策略。

已登记的 0.3.0-preview 原始图继续提供。制作时，本机热更新登记过 0.7.0-preview 的 640 像素物品图和 0.7.1-preview 的 512 像素物品图；它们画的是黑莓，与中文名称不一致。这两版记忆内容已通过既有召回流程停用，活动练习会关闭，旧请求不得继续提交。原图仍保存到 [历史预览目录](../../packages/visuals/archive/)，用于保留制作与问题证据；没有修改、删除或覆盖既有签名清单。0.7.2-preview 使用修正后的蓝莓图。

Web 首页使用当前预览图；进入第二版练习后必须使用该计划的已校验图，缺失时不会静默使用首页图。更早的 1.0.0 练习通过单独的动态模块加载原图，不占新首页的静态加载预算。当前本机服务显式保留这些已知历史素材；正式内容对象存储、自动保留周期和运营发布后台仍须建设。

下一次改动任务图片时：先冻结新交付文件、保存旧版字节，再变更内容版本；检查不可变版本、旧会话恢复、召回、报告分组和设备解码。不要在开发服务已登记某个版本后继续覆盖同版本文件。

## 4. 性能证据

- 网页当前四组图片：**1,060,704 字节**；原来首页三张 PNG 合计 6,100,114 字节。
- 当前练习目录的去重媒体（2 图集 + 3 MP3）：**730,254 字节**，此前 3,646,252 字节。
- Web 构建入口的保守静态依赖合计 **1,444,401 字节**，小于 1,500,000 字节。这里包括首页可能引用的全部当前图片、HTML、CSS 和 JS，即使不依赖 HTTP 压缩也满足此项预算。
- 构建命令会检查入口及其静态依赖，防止旧大图再次进入首屏；历史练习的按需模块单独计算。

这是构建文件体积检查，不是实测网络流量或首屏耗时。API 响应、HTTP 头、设备缓存、解码时延与弱网情况未包含。原生导出中确实含两份装饰 PNG，任务图集仍由签名内容下载；本轮未改原生依赖，也未重编译安装包。
