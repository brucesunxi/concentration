# 图片与固定语音素材库

版本：平台 v0.15.0 · 2026-09-30。适用于内部内容制作、方法、本地化、平台与测试团队。产品服务对象仍是全球家庭。

v0.28 补充：从源码开发内容生成 [四年龄双语语音缺口清单](qa/content-readiness-v0.28.md)，目前 32 个组合中仅 6 个接入匹配的固定 MP3；正式 `published` 内容缺 MP3 或音色 ID 将被拒绝。当前开发包和机器检查不构成真实听审，见 [本批验收](qa/content-readiness-v0.28-qa.md)。

## 1. 解决的问题

团队现在可以把制作好的 PNG 图集和 MP3 录音直接导入工作台，保留原始文件、制作来源、使用权声明和处理结果，再换入新稿、完整试玩、独立双审和发布本地预览。更换文件不能覆盖旧内容或沿用旧稿批准。

这是一条固定素材交付链路。应用只播放文件；导入过程不请求外部 TTS，不调用实时模型，不需要 API Key，也不录制儿童声音。技术检查通过不代表语音自然、字幕真实、许可充分或适龄性已获批准。

```mermaid
flowchart LR
  A[制作好的 PNG / MP3] --> B[记录来源、权利依据与年龄]
  B --> C[核对原文件摘要]
  C --> D[独立进程解码与清理元数据]
  D --> E[不可变素材库]
  E --> F[换入草稿并增加稿次]
  F --> G[冻结内容与完整试玩]
  G --> H[方法和语言独立双审]
  H --> I[签名本地预览 / 召回]
```

前后步骤分别见 [内容工作台](CONTENT-STUDIO.md)、[候选试玩](CANDIDATE-PREVIEW.md)、[图片交付规范](VISUAL-ASSETS.md)。

## 2. 编辑人员的操作

1. 用独立编辑账号登录工作台，打开「图像与声音库」。审核人与发布人可以阅读素材，不能代编辑上传。
2. 选择用途、文件、名称和制作时面向的年龄段。填写制作人/工具/版本及团队原始档案位置、使用权依据；这里保存声明，不上传合同或验证许可。
3. 图集须逐格检查顺序和跨格；声音须填写语言、音色或录音说明，以及逐字字幕。字幕由人核对，系统不自动识别录音中的话。
4. 点击「导入并检查」。成功后查看图像或试听声音，核对尺寸/时长、来源、原文件和交付文件摘要。
5. 打开自己可编辑的稿件，先保存文案，再从「从素材库换用文件」选择素材。只有用途、年龄和声音文字匹配的条目会出现。
6. 每次换用递增稿次和操作版本；冻结后进行本人当前稿完整试玩，再由方法、语言审核人分别审阅。发布人核对后只能发布 `LOCAL / reviewed-preview`。

填写未提交时，工作台主动切页、退出和重新读取被禁用。可明确「放弃尚未提交的填写内容」恢复空表单；浏览器强制关闭不会自动保存填写。切换素材用途会清空已选文件。页面内同一文件和说明可重试；强制刷新后不会记住重试标识，可能出现重复条目，但相同文件对象按摘要去重。

### 支持的格式

| 用途 | 技术规则 | 人工检查 |
|---|---|---|
| `characters` 动物图集 | 静态 PNG；正方形；边长 256–2048 且为偶数；按行四等分 | 左上小兔、右上狐狸、左下小熊、右下小猫；主体不跨格、辨识清楚 |
| `objects` 物品图集 | 与动物图集相同；不自动裁切或换序 | 左上苹果、右上叶子、左下花朵、右下莓果 |
| `guide` 固定指引 | MP3；实际解码时长 0.2–120 秒；非近乎全静音；当前 `zh-CN` / `en` | 母语听审、自然度、重音、停顿、清晰度和逐字对应 |

单文件上限 **5 MiB（5,242,880 字节）**；页面简写为 5 MB。导入器只检验格式和有限技术指标，不识别画中的动物，也不能证明录音语言。青少年当前使用代码图形，不能把儿童图集强行挂到不存在的槽位；可接入语言和文案匹配的声音。封面、背景、视频、SVG、任意图集布局、动态顺序播报和多声轨尚未提供导入入口。

## 3. 实际处理与质量边界

### PNG

核验签名、块边界和结束位置，拒绝动画控制块及尾随载荷；Sharp/libvips 在像素上限内完整解码，以 sRGB 静态 PNG 重新编码，移除输入元数据。尺寸、四格排列和透明度保留；没有“自动把主体摆正”或自动制作缩略图。图像转换可能改变颜色表示，因此仍须查看处理后的实际交付图。

实现采用 Sharp 的输入像素限制、错误级别和输出超时选项；默认不保留输入元数据。文档依据：[输入参数](https://sharp.pixelplumbing.com/api-constructor/)、[输出与超时](https://sharp.pixelplumbing.com/api-output/)、[依赖安全说明](https://sharp.pixelplumbing.com/security/)。这些选项不能证明图片没有恶意内容或解析器漏洞。

### MP3

强制按 MP3 输入，以受限管道运行 FFmpeg。先解码为 **24 kHz、单声道 float PCM，仅供分析**，测量时长、采样峰值、均方根电平和近满幅采样占比。低于当前工程阈值的近全静音文件被拒绝；其余电平只作人工排查信息，没有自动响度均衡或削波修复。

交付阶段复制压缩音频帧，移除标签、封面和其他流，不再次有损编码。分析采样率和声道数不是交付文件的编码承诺。现有无标签 MP3 处理前后可能逐字节相同。当前没有 LUFS、真峰值标准化、前后静音裁切、字幕语义校验或自然度模型。

FFmpeg 使用固定参数，不拼接上传文件名或命令；限制协议为 `pipe`、输入探测量、单次内存分配及输出大小。参数依据：[FFmpeg 命令说明](https://www.ffmpeg.org/ffmpeg.html)、[协议白名单](https://ffmpeg.org/ffmpeg-protocols.html)。`-max_alloc` 是单次分配限制，不是总进程内存上限；当前没有操作系统沙箱、杀毒引擎或容器内存限额。

### 运行约束

- 单个 API 进程最多同时处理 2 份文件；超额返回 429，保留文件后重试。
- 外层处理进程最长 25 秒；每次 FFmpeg 转换最长 10 秒，版本查询 3 秒；图像输出阶段设 8 秒超时。停止工作进程不是完整的操作系统进程树隔离，生产须补齐独立受限执行环境。
- 输入与输出均有限额，解码器诊断不直接写入响应或日志，避免传播不可信元数据。
- 422 表示该文件无效，导入进入 `rejected`；503 表示工具不可用或超时，保留 `awaiting` 可重试。容量、角色、摘要或传输错误不会伪装成技术检查通过。
- 原文件与交付文件分别存储、按摘要去重；两张对象表合计上限 256 MiB。最多 1,000 条导入记录，每个编辑最多 20 条未过期的待上传记录。当前没有归档、删除或扩容界面；到限额须由研发安排可审计的数据管理，不能直接删审核依赖对象。
- 待上传意图 24 小时到期。到期仅阻止上传，没有自动清理；成功素材不因这个时间失效。

所有数值是本地工程限制，不是科学质量标准或已完成的生产容量承诺。

## 4. 数据、内容与访问

迁移 **14** 增加三张表，未重写历史迁移：

| 表 | 用途与不变量 |
|---|---|
| `studio_media` | 编辑、制作声明、原始摘要/大小、状态、交付摘要、检查结果、创建/到期、幂等请求；完成状态必须有交付引用 |
| `content_media_sources` | 原文件摘要、字节数和 `bytea`；没有原文件下载 HTTP 路由 |
| `content_media_objects` | 处理后摘要、MIME、字节数和 `bytea`；读出时重新核对大小、摘要与扩展名 |

开始导入、失败、完成和换稿均追加审计。文件处理在数据库事务外执行，结束时在工作台全局写锁内重新验证账号、会话、拥有者、状态和容量，然后原子登记两个对象及素材结果。数据库管理员仍可直接改库；这不是防篡改存储。

换用素材时，内容包 `provenance` 绑定导入 UUID、原始文件 SHA-256 和标准化制作声明摘要。内容包同时绑定交付文件路径、摘要、大小、MIME；声音还绑定语言、音色说明和字幕。该声明本身不等于真实授权或专业审稿。

- 只有作者编辑自己未冻结的稿件；素材必须 `ready`、年龄范围包含本稿、用途匹配已有图像槽位。
- `guide` 语言必须相同，新附加的声音字幕必须与本稿 `rule` 完全一致，包含抑制任务。旧开发包中朗读 `strategy` 的文件保持原样，仍可用于本地预览；重新制作时需建立新稿次并附加完整规则录音。正式 `published` 内容若只朗读策略会被拒绝，技术匹配仍不能代替真人听审。
- 换用后开启新稿，冻结、试玩和双审都基于新摘要；已登记旧版及进行中的家庭计划不被替换。
- 原始文件只有本机数据库保存。工作台成员读取处理后文件须认证，响应 `no-store`。
- **新增的交付字节**必须被一份 `active` 的 `reviewed-preview` 或 `published` 清单引用，家庭媒体路由才返回文件。任一仍有效的发布引用均可使相同对象可读；它不要求当前渠道指针仍指向这份包，以便旧计划读取原资产。
- 已内置且本来公开的同摘要素材仍公开。把相同文件再次导入不会使既有公开字节变成私有；制作声明和导入记录仍受工作台权限保护。
- 召回最后一份有效发布引用后，服务拒绝新的公共文件读取；已下载/缓存字节不能被收回。当前媒体路由以登记的 active 状态判断，不独立检查发布到期；会话准备和客户端签名校验另执行到期限制。生产访问策略须明确 CDN 缓存、过期、撤回传播和旧会话需求。

## 5. 接口契约

所有路径以下省略独立工作台来源的 `/api/studio`。写入必须是同来源 Cookie、正确 CSRF；不能使用家庭身份或原生 Bearer。

| 方法与路径 | 权限及请求 | 行为 |
|---|---|---|
| `GET /library` | 四角色 | 最近 100 条；不返回幂等私有字段；尚无分页 |
| `POST /media-imports` | 编辑；UUID `Idempotency-Key` | JSON `{metadata,sourceHash,sourceBytes}`，最多 64 KiB；返回等待上传意图或同请求已有结果 |
| `PUT /media-imports/:id/file` | 创建该意图的编辑 | 原始二进制正文，`image/png` 或 `audio/mpeg`；不使用 multipart；上限 5 MiB；与意图的大小、SHA-256 完全一致 |
| `POST /drafts/:id/assets` | 稿件作者编辑；`Idempotency-Key` 和 `If-Match` | `{mediaId,slot}`；`slot` 为 characters / objects / guide；返回新稿详情 |
| `GET /media/:hash.ext` | 已登录工作台 | 处理后文件，`no-store`；不返回任意原始上传 |

`metadata` 公共字段：`kind,name,source,rights,rightsConfirmed:true,ageBands`。名称 2–100 字符，来源和权利依据各 10–500 字符；年龄数组从四组枚举中选择，不重复。图集另含 `layoutConfirmed:true`；声音另含 `locale,voice,transcript`，音色说明 2–120 字符、字幕 1–1000 字符。字段白名单严格校验；去掉字符串首尾空白后才入库和比较。

同一编辑同一个幂等键改变参数返回 409。二进制上传通过意图 UUID、原文件摘要及完成状态重试，不另要求幂等键；已完成仍须提交相同字节才能返回原结果。禁止同一意图上传其他编辑的文件。

常见响应：`MEDIA_SOURCE_CHANGED` 文件改变、`MEDIA_TYPE_MISMATCH` 声明类型不符、`MEDIA_IMPORT_EXPIRED` 超过 24 小时、`MEDIA_IMPORT_REJECTED` 原文件已失败、`MEDIA_TRANSCRIPT_MISMATCH` 声音文字/语言不符、`MEDIA_AGE_MISMATCH` 年龄不符、`MEDIA_PROCESSOR_BUSY` 并发满、`MEDIA_PROCESSOR_UNAVAILABLE` 处理工具不可用、`MEDIA_STORAGE_LIMIT` 容量满。实际解析错误另有格式/尺寸/时长/静音代码。

## 6. 部署与维护

Node 运行依赖包括 Sharp 0.35.4；FFmpeg 由操作环境提供，从 `PATH` 或 `FOCUS_FFMPEG_PATH` 读取。本轮在 Node 26.5.0、FFmpeg 8.1.1、libvips 8.18.6 验证。没有在所有最低支持 Node 版本、操作系统或 FFmpeg 构建上验收；供应商版本、安全补丁和许可分发须纳入生产部署清单。

```sh
ffmpeg -version
npm ci
npm run build
npm start
```

没有 FFmpeg 时，图片导入和既有文件播放仍可工作，新的声音处理返回可重试错误。可将 `FOCUS_FFMPEG_PATH` 指向本机已安装的可信可执行文件；不要把用户上传内容当作可执行文件。

所有对象随开发数据库持久化；重启不依赖上传临时文件。复制 PGlite 数据前先停止服务，保留整份 `FOCUS_DATA_DIR` 及已有私密身份资料的访问保护。`npm run build` 不导出数据库中的导入内容到静态目录。生产需迁移到隔离原件桶、发布对象桶和专用处理任务，补齐总资源限制、扫描、版本锁定、备份恢复、删除/保留和审计归档。
