# 孩子年龄档与成年转换：实施契约

2026-10-01。v0.45 已实现家庭创建者发起的年龄档复核、待生效转换、旧练习保护与 6–17 岁档间生效流程；18 岁后的独立权利转换仍需单独建设。长期家庭使用会让内容分龄和监护许可逐渐失准；不能仅在界面上改一个年龄标签。以下是 D02/D03 的实施契约与当前边界。

## 状态与家庭操作

| 状态 | 新练习 | 已签发的练习与记录 | 家庭操作 |
|---|---|---|---|
| 当前档有效 | 按市场、许可与日额度检查 | 按原签名和内容版本继续 | 创建者可发起复核 |
| 待复核 | 暂停签发新练习；不把暂停说成孩子失败 | 原设备在原授权期限内可结束和补传 | 创建者重新验证身份，确认实际年龄档与所有设备的同步状态 |
| 变更待生效 | 不再签发旧年龄档的新练习 | 保留旧计划、事件、内容摘要与补传期限；不清除本机未同步日志 | 显示未结束／待补传记录及最晚有效期限 |
| 新档生效 | 只用新档选择内容、额度、市场与许可 | 旧记录按当时年龄档、设备和内容条件保留；比较不可混入新档 | 旧孩子会话轮换；必要监护核验重新完成 |
| 超出 6–17 岁 | 暂停新练习 | 保存已有资料和可核对状态 | 按地区政策完成独立身份与共享权限转换，不能自动把购买者视为成年人的数据代理人 |

## 后端不可省略的约束

1. 年龄复核与变更只能由已重新验证的家庭创建者发起；提交绑定当前档案版本和幂等标识。重复或并发提交只会有一次成功，旧表单须重新读取。
2. 变更前列出服务端未结束、换设备、待补传练习。新练习可立即暂停，但旧签名记录要在原授权边界内有保存／结束路径；无法确认其他离线设备时，不宣称所有记录已同步，也不主动清除本机日志。
3. 年龄档和语言影响内容、语音、日额度、监护告知与国家准入。变更生效时逐项重新核对，旧年龄的监护证明不得自动继承；本地试玩确认也须重新展示。未满足新组合许可时维持只读资料入口。
4. 每次练习使用创建时保存的年龄、语言、内容版本与规则解释，历史周回顾按条件分组。不能把旧成绩重新解释为新年龄的表现，不能修改旧事件或重新签发已关闭练习。
5. 18 岁转换与监护争议是独立权利流程。当前只有家长创建的档案和孩子作用域，并无可证明的孩子本人身份或出生日期；仅按“建档满一年”提醒不能判断法定年龄。正式实施前需地区政策、身份、资料访问和支持流程审查。

## 建议接口与验收

档案现有单调递增的复核版本、复核时间、下一次复核时间及待生效转换状态；没有在记录表重复可变年龄。`GET /api/children/:id/age-review` 显示未结束练习及补传期限；`POST` 以 `If-Match`、幂等键和已重新验证的家庭创建者身份确认当前档或提出新档；`POST .../apply` 再次检查版本和未结束练习后生效。跨档生效撤回旧本地确认、要求本地预览重新确认、清除孩子会话并重置分龄进度和日额度。正式批准模式下旧年龄的监护核验不会自动继承。家长 Web 与原生均有双语入口；孩子只看到“家庭正在更新适合你的安排”。

当前 365 天是产品复核周期，不是出生日期或法定年龄判断；没有验证真实生日。已签发且未结束、仍在补传期限内的练习会阻止生效，旧设备可按原授权补传。旧签名练习保存原计划年龄，周回顾按年龄及其他条件分组。对**所有未结束练习的补传期限均已过**的情况，年龄档变更页现在逐条标出到期状态，要求家长额外确认原设备上未上传的步骤不能再合并；服务端在同一事务中只关闭确已到期的活动练习，保留已收到的事件和原额度，不生成完成结果，不删除本机日志。旧版无期限授权或仍可补传的练习继续阻止变更。真实设备上的本机导出与家长理解仍待验收。18+ 只进入暂停状态，不能自动生效。

最低验收矩阵：同档确认、相邻档升级、录入错误纠正、跨 18 岁、两个家长并发、旧页重试、跨午夜、旧设备离线、换设备、已撤回采集、内容召回、新市场关闭、许可到期、删除档案、数据库重启与覆盖升级。分别验证 Web Cookie、原生 Bearer、家庭隔离和 PostgreSQL 行级策略。任何一条路径使已保存记录无法读出或让旧许可继续签发新练习，都阻止发布。

本契约只是可评审的工程设计。身份、地区法律与儿童发展研究的结论由相应负责人确认后才能打开真实家庭流程。
