# 任务协议与内容发布实现

版本：本地应用 v0.15.0，任务引擎 2.0.0，难度策略 conservative-2。本文供前端、移动端、服务端、内容与测试团队实现和联调使用。当前内容全部是成人开发评审材料，未完成真实家庭适用性验证。

## 本次实现的边界

任务计划、事件、素材与评分现在绑定到同一内容版本。设备或输入方式改变时，另建可比较的记录序列；出现计时、素材或显示异常的步骤不再算作孩子漏答。旧版记录继续由保留的 1.0.0 引擎解释。

内容发布模块可以验证发布人及两名独立审核人的签名，拒绝修改既有版本，并保存召回记录。当前 32 个开发组合全部标为未审核；程序测试中使用的模拟审核签名不能当作真实专业人员的批准。v0.13 已提供独立本地身份与内容工作台，见 [编辑/审核/发布操作设计](CONTENT-STUDIO.md)。v0.14 新增 [候选试玩与回放核对](CANDIDATE-PREVIEW.md)，通过审核必须绑定本人当前稿的完整试玩。v0.15 接通 [PNG/MP3 素材导入与换稿](MEDIA-LIBRARY.md)，文件、字幕及制作声明均绑定到新内容摘要。完整素材制作、真实批准、企业身份、生产密钥托管与信任配置仍需建设。

## 版本及比较条件

| 对象 | 当前值或字段 | 实现约束 |
|---|---|---|
| 应用 | 0.13.0 | 表示本批工程版本 |
| 新任务协议 | 2.0.0 | 既有 1.0.0 计划走冻结的旧回放函数 |
| 难度策略 | conservative-2 | 不与旧规则的证据直接合并 |
| 参数集合 | foundation-2 | 解释器内的受限参数集合，内容不携带可执行代码 |
| 内容 | id、version、sha256 | 六个原有中文儿童包为 0.7.2-preview，26 个新增固定语音包为 0.7.3-preview；同 id/version 不能替换字节内容 |
| 环境 | platform、deviceClass、input、modality | web/ios/android；desktop/tablet/phone；pointer/touch/keyboard；当前只有 visual |
| 可比较条件 | 引擎、策略、内容 hash、任务、年龄、语言、模态、平台、设备类别、输入、难度 | 任一变化都产生另一条比较序列 |

开始新会话时，服务端查找同一环境及内容的最近已完成记录，沿用其难度决定；没有匹配记录则从 1 级开始。结束后的升级证据只取相同条件最近 14 天内的最近 3 次完整会话。不能跨过最近的帮助或中断记录，挑出更早的好成绩进行升级。自由选择任务与推荐课程的完成进度仍独立处理。

环境字段由客户端报告，用于分层与排查，不是设备认证。事件重算也不能证明操作者身份或阻止所有被篡改的客户端。

## 计时与异常处理

以下数值是当前工程阈值，尚未由跨设备研究或儿童试验验证，不能称作标准化评估参数。

| 条件 | 当前规则 | 对记录的影响 |
|---|---|---|
| 计时题响应 | 首次点击不提前结束刺激窗口 | 等待完整窗口后提交 |
| 重复点击 | 保存 responseCount 与 firstResponseMs | 单题命中/误反应的分母仍只有一次机会 |
| 同一正式块内间隔 | 提交到下次呈现至少 1000 ms | 过短事件序列被拒；客户端显示空白间隔 |
| 初始显示证据 | 必须报告 assetsReady、frameDeltaMs、method | Web 使用相邻动画帧；原生协议预留 native-frame |
| 帧间隔大于 100 ms | 标记 render_failure | 排除本步骤，恢复时重做 |
| 计时回调晚于窗口超过 250 ms | 标记 timer_late | 排除本步骤，恢复时重做 |
| 计时题反应早于 100 ms | 标记 premature_input | 排除本步骤，不解释为能力差异 |
| 输入方式与计划不同 | 标记 input_changed | 排除本步骤；切换输入需新条件会话 |
| 页面后台、暂停、刷新、素材异常 | 明确中断原因 | 不生成漏答或错误结果，不推进题号 |

排除步骤仍消耗已经发生的有效练习时长，不能通过反复暂停重置日额度。正式题连续三次错误时，客户端安排规则回顾和休息入口；这条交互仍待新版浏览器与真实设备验收。搜索和记忆的理解检查要求连续完成两道不同例题；帮助或错误会重新开始检查。

动画帧时间是浏览器呈现质量的近似信号，不是屏幕像素实际亮起时刻。当前实现尚未完成刺激出现到输入可用之间延迟的设备校准，也没有物理显示测量或原生端证据；不能据此对外提供毫秒级反应时测评或临床结论。

## 内容验证流程

1. 服务端为会话选择已登记、未召回且未过期的内容，冻结内容引用。
2. 客户端读取发布清单和受信公钥，验证签名、内容摘要、有效期、市场、任务、年龄、语言和协议依赖。
3. 按清单下载素材，限制下载时间与字节数；计算 SHA-256，确认长度与摘要完全匹配。
4. 图片先解码，之后使用本机 blob 地址显示。音频只播放与同一份文案匹配的固定 MP3。
5. 下载、解码或验证失败时阻止进入练习，允许返回家庭空间。

发布清单使用 P-256 ECDSA/SHA-256，签名为 WebCrypto 输出的 64 字节 r/s 形式，编码为 128 个十六进制字符。签名前，嵌套对象按键名排序，数组保持原序，再以 UTF-8 编码。当前契约限于严格校验的 JSON 数据；它不是通用跨语言规范化标准，移动端必须用共同测试向量验证实现。

素材路径采用 `/content-assets/<sha256>.png` 或 `.mp3`，既有路径不可覆盖；单包素材合计上限 20,000,000 字节。该上限防止异常下载，不等于产品的首屏性能目标。

### 发布和审核角色

| 角色 | 当前验证责任 |
|---|---|
| 作者 | 在发布清单中声明作者身份 |
| 方法审核人 | 以独立受信密钥签署内容 hash、角色、时间和审核证据 |
| 语言审核人 | 对相同 hash 签署语言及适龄审查记录 |
| 发布人 | 签署整个发布清单；不能兼任上述必需审核人 |
| 受信身份管理 | 由服务端受控信任库提供；内容包不能自己声明某个新密钥可信 |

公开发布包必须有完整内容/素材批准标记、两个不同人员的审核签名及发布人签名；作者也不能充当这两名审核人。修改文案、素材、年龄或其他内容会改变 hash，原批准不能继续用于修改后的内容。

本机开发包使用 `local-preview`、唯一市场 `LOCAL`，没有伪造的人类批准。开发签名密钥在本机生成，仅用于内容完整性校验，不是 Azure/API 密钥，也不需要购买外部服务。生产模式仍被启动门槛阻止；生产客户端还必须使用独立配置的受信根，不能信任同一次网络响应自带的公钥。

另有 `reviewed-preview` 本地审核预览通道：必须具备两种独立角色的签名与发布人签名，且只能用于 `LOCAL` 和本地模式。工作台按任务/年龄/语言切换新计划的选包指针，不改变已有计划；生产模式拒绝这一通道。自动测试生成的审核记录不代表真实专业批准。

### 召回和恢复

召回先在事务中锁定并关闭内容版本，保存操作者、时间与理由。重复召回仍会继续清理尚未关闭的关联活动会话，避免进程中途退出留下可继续练习的会话。活动会话被撤销，其保留日额度按已预留预算计算，这是当前保守处理，后续须提供向家庭解释的产品流程。

创建、恢复、事件补传及最终提交都会重新检查内容状态。检查发生在重复事件返回之前，因此旧请求不能通过“重试”绕过召回。当前已打开客户端另设 30 秒轮询，在重新联网、获得焦点或回到前台时检查状态；成功得知内容不可用后停止操作和音频。

30 秒不是全场景召回保证：网络超时、断网和系统调度都会增加延迟。v0.9–v0.12 已接入签名续练授权和两端恢复边界，详见对应实施文档；推送及多设备实时撤回传播尚未实现。v0.13 工作台已提供独立发布角色的本地召回入口，家庭身份不能调用；真实设备召回演练与生产管理体系仍待完成。

## 内容制作清单

执行 `npm run content:audit -- --out docs/productization/qa/content-inventory-v0.7.json` 可以重新生成源素材清单。该命令创建内存测试库，不读取家庭数据库或持久化开发私钥，不调用任何语音服务。

当前实测结果：

- 4 类任务 × 4 个年龄段 × 2 种语言，共 32 个内容组合。
- 32 个均为未审核开发内容。
- 6 个组合有音频：中文 6–8 和 9–11 岁的搜索规则、过桥策略、记忆规则，复用 3 份 MP3。
- 内容包使用 2 张图集和 3 份 MP3，共 5 份不同素材，总计 730,254 字节；不包含家庭首页装饰图。
- 英文、青少年、目标监测、动态顺序播报及完整纠错语音待制作与审稿。

四组位图已重新生成并接入；旧版与中间预览图继续服务原有计划。完整提示词、原图、交付尺寸和预算见 [图片交付规范](VISUAL-ASSETS.md)。分龄辨识、文化适用性和设备显示审核仍未完成。自动摘要校验只能证明收到正确字节，不能判断音色自然、发音清楚、图片精致或文化适用。
