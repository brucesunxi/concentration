# 家庭 Web：小屏导航与键盘操作

v0.25 / 2026-10-01。面向全球家庭的中英文 Web 体验改进，沿用四年龄段、家长与孩子的既有权限。原生安装包仍为 v0.24；本批不代表原生设备验收完成。

## 1. 问题与结果

原先手机导航把七个入口放在一行并隐藏文字。在 320 CSS 像素的浏览器视口，页面实际内容宽度达到 347 像素，最右入口溢出；不熟悉图标的家长和孩子难以识别页面。长昵称、英文标题和表单也需要更充分的换行空间。

现在 900 像素及以下采用四个常用入口：今日探索、生活小目标、成长记录、更多。图标始终配有文字；“更多”打开含全部页面的菜单，显示当前页及需家长权限的入口。宽屏继续使用侧栏。

## 2. 可执行的交互规格

| 场景 | 规则 | 验收要求 |
|---|---|---|
| 常用导航 | 四等分，按钮至少高 60px；底部考虑系统安全区 | 无横向溢出；正文底部留出导航空间；中英文均可识别 |
| 完整菜单 | 原生模态对话框；单列入口至少高 56px；最多占视口高度减 20px | 窄屏可滚动；背景不可操作；关闭按钮至少 48px |
| 权限 | 菜单复用现有导航守卫；协作家长继续遵循可访问范围 | 孩子打开家庭空间先显示家长验证；菜单不赋予额外权限 |
| 键盘 | Tab/Shift+Tab 在弹窗内首尾循环；Escape 关闭 | 关闭后回到原入口；入口因尺寸变化消失时回到页标题 |
| 页面切换 | 导航后聚焦主标题，并滚动到页首 | 键盘用户不必重新遍历整页导航；跳转链接可直达主体 |
| 昵称与标题 | 长文字换行；小屏档案使用两列 | 不以隐藏溢出掩盖内容；保留年龄和选中状态 |
| 表单 | 小屏输入字号 16px，输入区域至少高 48px | 空账号表单可阅读、可关闭；实际软键盘仍需设备验证 |
| 练习界面 | 家庭页面尺寸规则限定在家庭、欢迎和恢复容器 | 不因家庭导航修改任务刺激尺寸、输入窗口或计分协议 |

协作家长的常用第二入口为“练习与休息”，与现有生活目标权限一致。服务端仍是权限判断的依据；界面锁图标仅作提示。

## 3. 技术实现与交接

- `apps/family-web/src/App.tsx` 维护同一份页面清单，供侧栏、常用导航和完整菜单使用；页面跳转继续调用现有 `navigate`。
- 共享 `Dialog` 提供独立标题关联、中英文关闭名称、键盘边界循环和关闭后的焦点恢复。回调通过引用读取最新值，避免仅因渲染就反复关闭、打开弹窗。
- `apps/family-web/src/compact.css` 覆盖家庭页面响应式布局；在原样式之后加载。600px 以下处理表单和文案，900px 以下启用底部导航。
- schema 保持 25，无新依赖、数据库迁移或 API 契约；服务健康版本与 Web 版本更新到 0.25.0。
- 按既有不可变发布流程构建。旧标签页仍可保持其原运行版本；要验收新版本，应关闭本站旧标签后重开并核对入口资源。

## 4. 已有证据与下一步

构建及类型检查通过；内置浏览器检查了 320、390、768、1024 CSS 像素下的家庭页面，以及中英文导航、长昵称、生活目标选择、家长课目录、键盘循环和孩子权限入口。详见 [v0.25 验收](qa/compact-family-v0.25.md)。

这只覆盖浏览器视口模拟。测试团队仍须在选定 iOS/Android 设备验证触摸、软键盘、系统字体放大、读屏、横竖屏及安全区；产品团队需用真实家庭验证四入口名称是否易懂。其他语言和 RTL 布局不能从中英文结果推定通过。
