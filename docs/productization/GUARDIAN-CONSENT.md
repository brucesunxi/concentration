# 监护核验与用途同意：v0.37 工程边界

日期：2026-10-01。目标是让家庭产品在每个获准的国家、年龄、语言和平台组合中，只有取得可核验的监护人许可后才开始采集孩子练习数据。**当前没有真实核验供应商、正式告知文本或真实市场发布；本地服务仍只允许虚构地区 `ZZ`，生产入口仍拒绝启动。**

## 已实现的服务端行为

1. 本地试玩与正式许可分开。本地 `acknowledgedLocalUse` 和孩子档案的 `localConfirmation` 只在 `local-development` 模式起作用。注入批准矩阵时，这两个字段不能开启练习、观察、生活目标或家长协作范围。
2. 批准矩阵每条规则必须指定监护同意告知文本的版本和 SHA-256。相同国家、年龄、语言在不同平台不能指向互相冲突的告知文本。规则身份把告知文本和三方审批引用一起绑定；变更后旧许可不自动迁移。
3. 迁移 29 新增 `guardian_consents`：家庭、孩子、创建者、供应商、核验交易引用的哈希、地区、年龄、语言、用途、告知文本、准入矩阵身份，以及核验/授予/到期/撤回时间。数据库外键约束家庭与孩子、创建者一致；受限运行角色使用家庭行级隔离。**不保存身份证件、监护人姓名、原始交易引用或原始凭证。**
4. 只在服务端内部提供 `grantGuardianConsent`，需要已重新验证的家庭创建者身份。它要求受信任适配器向供应商核验一次性令牌，并返回成人监护资格、明确用途同意和精确绑定字段。服务端拒绝跨孩子、跨家庭、跨创建者、旧告知文本、旧市场清单、未来时间、过期凭证和交易重放。**没有将这个方法暴露为当前 HTTP 路由，客户端不能自行提交“已经核验”布尔值。**
5. 每次采集在服务端查询当前未撤回、未过期、与孩子属性及当前准入身份匹配的记录。家长停止采集与记录撤回、活动会话关闭、孩子凭据删除在同一家庭事务边界内执行；已确认的旧记录仍可导出或删除。导出格式 v2 增加已脱敏的许可历史，不含核验引用哈希。
6. v0.37 将外部供应商核验放在家庭数据库事务之外，并设置 8 秒中止期限。核验前后均重新确认登录、创建者身份、孩子未撤回及当前开放范围；最终写入时重新比对供应商证明与最新状态。供应商慢响应不能持有家庭事务，撤回先完成时迟到证明会被拒绝。
7. 服务端向 Web 与原生返回明确的 `collectionStatus`：本机试玩可用/未开放、监护核验有效/待核验、已停止采集。客户端使用同一双语文案；旧服务缺少字段时显示无法确认并禁止暗示可继续采集。该字段只解释服务端决定，客户端不能据此自行放行练习。

## 后续接入要求

- 产品和法务按国家、年龄、用途批准真实告知文本及留存期限；选定可核验成人监护资格与同意的服务商，明确失败、争议、账户恢复和年龄升级流程。代码中的三方审批引用不证明真实审批，也不能替代地区法律判断。
- 身份团队实现服务器到供应商的安全交换或已验证回调。适配器必须核对签名/渠道、单次交易、时效、真实成人及监护关系、告知文本和用途；不能把浏览器字段原样包装为证明。要加入重放存储、回调重试与供应商故障隔离，并避免在日志里记录凭证。
- 家庭端提供能理解的家长告知和同意步骤，只有核验成功后才提示可以开始。没有核验供应商时保持“尚未开放”，不把本地预览勾选框换个标题当成正式同意。
- 基础设施团队用独立 PostgreSQL 运行角色执行迁移/权限/并发套件，验证家长、协作家长、孩子作用域与行级隔离；演练撤回与供应商回调竞态。当前只有 PGlite 集成测试覆盖核验逻辑；独立 PostgreSQL 套件本批未运行。
- 客户端离线时仍可能持有以前签发、未到期的练习授权。联网后服务端会拒绝失效许可的上传；即时跨设备撤回还需要设备信号与运营处理，不能宣称已解决。
