# 家庭历史记录：稳定翻页与权限保护

v0.26 / 2026-10-01。Web 与原生家长记录页已接入练习、生活观察的独立翻页。[v0.26 原生安装包](qa/native-package-v0.26.md) 已交付，iOS 模拟器安装和代码摘要核验通过；设备界面验收继续按原生交接进行。

## 1. 用户行为

原页面最多显示最近 50 条练习与 50 条观察，没有进入更早记录的入口。现在两类记录各有“更早”“返回上一页”和当前页条数；末页明确说明已到当前可查看的最早记录。

每页最多 50 条，页面只保留两类当前批次，避免不断追加全部历史。翻练习不会改变观察页码，反之亦然。“查看最新记录”从两类首页重新读取。新保存的观察会刷新历史；切换孩子重新开始，不沿用另一个档案的页码。

等待与失败提示放在正在操作的翻页入口旁。连接失败保留原页和页码，按钮恢复后可重试；只有成功响应才能前进。Web 成功翻页后聚焦对应记录标题。读到权限失效时清除私人记录，要求重新验证；周回顾也不留在失效的历史视图中。

## 2. 接口与排序

沿用 `GET /api/children/:id/report`。可选查询参数：

| 参数 | 含义 |
|---|---|
| `sessionsCursor` | 上一批练习响应提供的位置；省略则读取最新一页 |
| `observationsCursor` | 上一批观察响应提供的位置；省略则读取最新一页 |

两个参数独立，均最长 512 字符。未知字段、重复参数、空值和错误类型被拒绝。响应保留原来的 `child`、`sessions`、`observations`、`observationCount`，新增：

```json
{
  "history": {
    "version": "family-history-1",
    "pageSize": 50,
    "sessions": { "nextCursor": null },
    "observations": { "nextCursor": null }
  }
}
```

`null` 表示没有下一批。每类按 `(created_at DESC, id DESC)` 排序，最多取 51 条以判断是否还有记录，返回前 50 条；后续使用严格小于上一批末尾二元组的条件。没有使用随新增记录移动的 OFFSET。

时间从数据库直接格式化为 UTC、六位小数，保留微秒；不能先转成 JavaScript Date 再生成游标，否则同一毫秒内的记录可能遗漏。UUID 在时间相同时提供稳定顺序。练习只包含已有结果的记录，未确认练习仍由原恢复入口处理。

本次复用已有按孩子与时间建立的索引，schema 保持 25。现有测试不代表生产大数据量性能已通过；生产部署前仍须按真实规模检查执行计划与延迟。

## 3. 一致性和权限边界

游标只编码协议版本、孩子 ID、集合名称、时间和记录 ID，属于可校验的位置描述，不是秘密或授权凭证。服务端每次先在现有事务内重新验证身份、成员状态和孩子范围，再校验游标与目标孩子/集合一致。知道或修改游标不会扩大权限。协作家长撤销后，先前拿到的位置也不能继续读取。

这不是跨请求冻结快照。新增记录或迟到的练习结果可以通过“查看最新记录”读取；权限、删除和结果确认仍按请求当时的状态生效。返回上一页会重新请求该位置，不从本地恢复已撤销的数据。边界记录被删除不影响游标继续定位。

旧客户端仍可读取默认首页和原字段；新客户端要求 `family-history-1`，面对旧服务明确提示不兼容，不假装已经显示完整历史。页面只在内存保存位置和当前记录，没有新增儿童数据持久缓存。
