# PostgreSQL 家庭隔离与运行交接

v0.19 为独立 PostgreSQL 增加受限运行身份、家庭行级隔离、显式初始化和真实并发验收。默认本机 PGlite 继续用于开发。此交付解决数据库层的部分可靠性要求；生产准入、备份恢复、容量验证与独立青少年身份仍未完成。

## 1. 身份与职责

| 身份 | 使用位置 | 权限边界 |
|---|---|---|
| 迁移身份 | `npm run db:prepare` 独立进程 | 拥有专用应用库的表，执行迁移、注册开发内容和签名公钥、为既有运行角色授权 |
| 家庭运行身份 | `DATABASE_URL` | 家庭表受行级策略限制；内容只读；不能创建表、修改迁移记录或读取工作台身份 |
| 工作台运行身份 | `FOCUS_STUDIO_DATABASE_URL` | 编辑、审核、媒体与发布数据；不能直接读取或修改家庭表 |

PostgreSQL 表所有者通常绕过行级策略，超级用户和 `BYPASSRLS` 角色也会绕过；`TRUNCATE` 不受行级策略约束。因此运行时会拒绝这些身份或相关越权能力，而不是仅检查策略是否存在。[PostgreSQL 16 行级安全](https://www.postgresql.org/docs/16/ddl-rowsecurity.html)

v0.24 启动要求运行角色可只读迁移表，且最高版本恰为 25；旧版或未知新版拒绝启动。启动还检查角色所属高权限角色、表所有权、十三张表的策略数量、跨界表权限、必要授权及专用函数权限。出现额外策略、缺少策略、家庭与工作台角色混用时拒绝启动。管理员仍属于可信边界；启动检查不证明管理员未篡改函数或策略表达式。

家庭和工作台目前仍可由同一个本机进程启动，使用不同连接池。这是数据库权限分离，尚不是生产进程、主机或密钥服务的隔离。

## 2. 请求如何限定家庭

服务通过已认证 `Principal` 建立请求上下文。每次从连接池取出连接后开启事务，并使用事务内配置写入十二个上下文字段。未使用的字段也写为空；提交、回滚与下一次借用都会清除上一次请求的作用域。单条查询也走同一流程。

| 上下文 | 允许读取的范围 |
|---|---|
| 无上下文 | 十三张家庭表均无可见记录 |
| 创建者 | 当前家庭全部孩子；敏感业务操作仍检查最近验证 |
| 协作家长 | 活跃成员只见指定孩子；家长作用域不可见生活目标与动作；待确认时无可见孩子 |
| 孩子 | 当前家庭、绑定孩子及该孩子的练习和生活记录；兄弟姐妹不可见 |
| 登录 | 规范化家庭名称及家长登录名对应的身份记录 |
| 成员核验 | 令牌已绑定的家庭/成员 ID |
| 接受邀请 | 仅匹配邀请摘要的家庭、邀请和待确认成员写入 |
| 令牌认证 | 当前令牌摘要对应的会话 |
| 注册 | 新生成家庭 ID 的创建与家长令牌写入，二者同事务 |

家庭表包括 `families`、`children`、`auth_sessions`、`local_confirmations`、`sessions`、`events`、`observations`、`life_goals`、`life_goal_actions`、`session_handovers`、`family_members`、`family_invitations`、`family_member_audit`。子表通过可见孩子、练习或目标限定归属。签发孩子凭据时，还检查该孩子在当前家庭可见。

数据库上下文由受信服务设置，不接受客户端传入的家庭作用域。本层主要防御遗漏查询筛选和连接复用错误；数据库账户或应用服务器已被攻破时，攻击者可以自行设置上下文。因此它不替代参数化查询、API 授权、会话验证、个人分享权限或生产身份服务。

## 3. 事务与内容召回

v0.20 家庭业务在执行事务中先锁定家庭行、重新核验登录，再进入孩子/练习操作；内部事务加入外层同一连接。密码更新、全退出和旧密码登录以家庭行协调。该设计串行化同一家庭操作，长报告与导出的容量仍待验证。见 [账号执行边界](ACCOUNT-SECURITY.md)。

同一事务始终使用同一个连接；借用期间和连接闲置期间分别处理断连。发生错误时回滚；无法回滚的连接从池中移除。当前连接池上限为 8，连接等待 5 秒，语句与空闲事务超时 15 秒，等待锁超时 5 秒。这些值是开发配置，尚无生产容量依据。[node-postgres 事务要求](https://node-postgres.com/features/transactions)

迁移 1–25 在一项带数据库互斥锁的事务中运行，避免多个初始化进程争抢版本记录。内容与密钥初始化另用串行事务；已存在的内容版本和签名文件继续复用。当前采用失败后整体回滚，不提供自动向下迁移。

家庭服务需要在内容版本上持有共享锁，以协调新练习与召回。它通过固定 SQL 的 `focus_locked_release` 获取锁，不获得内容表写权限。工作台召回后，通过 `focus_revoke_recalled_sessions` 关闭相关活动练习；函数只接受已召回摘要，按孩子和练习顺序锁定，不返回家庭资料。两个函数都固定搜索路径并撤销公共执行权限。行锁持续到事务结束。[PostgreSQL 锁机制](https://www.postgresql.org/docs/16/explicit-locking.html)

这两个函数以表所有者权限执行，需要纳入安全评审。大规模召回的分批任务、积压监控和自动重试仍待建设。离线设备即时收到召回也尚未实现；服务端重新收到操作时会核验召回状态。

迁移 19 新增家庭练习安排与会话上限快照，范围约束受分龄上限限制，继续使用原有家庭行级策略。旧服务不执行新上限，升级须停止全部旧 API；详见 [安排迁移](PRACTICE-LIMITS.md)。

迁移 20–24 新增成员账号、邀请和审计，升级旧家庭凭据，并保护孩子范围、成员状态写入和家长作用域的生活回顾。完整说明见 [家长协作](FAMILY-MEMBERS.md)。

## 4. 团队如何复现验收

本机已有 Docker 和缓存的 `postgres:16-alpine` 镜像时，运行：

```sh
npm run test:postgres
```

测试脚本不读取 `DATABASE_URL`，不连接现有业务库，也不自动拉取镜像。它读取本地镜像 ID，创建随机名称、随机密码的专用容器，仅绑定 `127.0.0.1` 的临时端口；数据目录使用临时内存文件系统。测试结束只删除自己创建的容器及临时文件。可通过 `FOCUS_DOCKER` 指定 Docker 可执行文件，`FOCUS_PG_TEST_IMAGE` 指定另一份已缓存镜像。

此次实际版本是 PostgreSQL **16.14 / arm64**，不是对其他数据库大版本的兼容承诺。15 项检查及完整镜像摘要见 [当前验收](qa/family-content-v0.24.md)；此前数据库首次验收见 [v0.19 记录](qa/postgres-v0.19.md)。80 项并行读取用于发现作用域混用，不是吞吐量或在线家庭数的承诺。

## 5. 配置独立开发数据库

1. 数据库负责人创建一个专用开发库及迁移身份，并创建两个不同的运行角色。运行角色应为 `LOGIN NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE`，不加入管理角色。角色名仅接受小写字母开头的小写字母、数字和下划线，最长 63 字符。通过数据库管理工具设置密码。
2. 由本机安全环境提供 `DATABASE_MIGRATION_URL`，指向该库的迁移身份；提供 `FOCUS_DATABASE_ROLE` 和可选的 `FOCUS_STUDIO_DATABASE_ROLE`；将 `FOCUS_DATA_DIR` 指向专用的绝对目录。该命令会撤销 `public` schema 对 `PUBLIC` 的创建权限，因此不能在与其他应用共享的库内直接运行。
3. 执行 `npm run db:prepare`。成功输出 `DATABASE_PREPARED` 和 schema 26，不输出连接串或密钥。此步骤注册的仍是本地开发内容，没有创造专业审稿批准。
4. 从运行环境移除 `DATABASE_MIGRATION_URL`。将 `DATABASE_URL` 设置为家庭运行身份，保持同一个数据库和 `FOCUS_DATA_DIR`，执行 `npm start`。运行服务不会自动迁移、创建内容签名私钥或注册公钥；缺少准备数据会拒绝启动。
5. PostgreSQL 模式下工作台默认关闭。需要启用时，给出同一数据库的 `FOCUS_STUDIO_DATABASE_URL` 并明确设置 `STUDIO_PORT`。工作台角色必须通过独立权限检查。管理账号仍按 [工作台交接](CONTENT-STUDIO.md) 配置；管理命令读取工作台连接，不复用家庭连接。

只为本机 PGlite 开发时，不设置这两项数据库连接，原有启动步骤继续有效。PGlite 以拥有者身份运行，并未获得此次真实 PostgreSQL 的运行身份隔离。

已有独立 PostgreSQL 开发库升级时，先停止连接同一库的全部旧版 API（不得滚动混用旧版与 v0.24），确认数据库备份与当前签名目录，再用迁移身份运行准备命令，最后以新运行身份启动。不要将原有超级用户连接串直接留在 `DATABASE_URL`；新版会拒绝它。回退需恢复同一批数据库和签名目录，不能只删除版本记录或撤销策略后继续运行。

## 6. 尚未关闭的发布要求

- 在选定托管数据库、TLS 和真实部署拓扑上复验；数据库账户、迁移账户、签名密钥分别管理与轮换。
- 多家庭容量、长时间运行、慢查询、连接耗尽、自动重试和数据库主从切换。
- 备份恢复、删除标记及恢复后防复活、跨区域策略与供应商清理。
- OIDC、可验证监护同意、正式家庭成员身份与独立青少年身份、细粒度共享授权。
- 工作台完整发布审核流程的 PostgreSQL 并发矩阵和召回任务化。

`APP_MODE=production` 继续拒绝启动。本文件描述工程能力与复现方式，不构成上线批准或训练效果证据。

迁移 25 新增家庭内容发布/渠道和独立审稿表，家庭只读发布记录，工作台不能访问家庭目标。`life_goals.content_hash` 保留目标版本引用；`focus_locked_family_content(text)` 提供与召回更新互斥的固定只读锁查询。已通过真实发布及召回并发检查，详见 [内容发布交接](FAMILY-CONTENT.md)。
