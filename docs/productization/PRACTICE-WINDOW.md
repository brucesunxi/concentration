# 单次练习期限与休息询问

v0.22 · 2026-10-01。新练习使用第 2 版续练授权；数据库仍为 schema 19，原生壳仍为 0.2.0。本批在已有有效任务日上限之外，限制一份已准备练习的总期限，并在安全间隙询问孩子是否想休息。

## 1. 产品规则

| 年龄段 | 一份练习从服务端准备起最长保留 | 首次休息询问时间 |
|---|---|---|
| 6–8 | 20 分钟 | 4 分钟后到达安全间隙 |
| 9–11 | 25 分钟 | 5 分钟后到达安全间隙 |
| 12–14 | 30 分钟 | 6 分钟后到达安全间隙 |
| 15–17 | 30 分钟 | 6 分钟后到达安全间隙 |

**这些是待验证的开发参数，不是建议使用量、医学建议或治疗剂量。** 一般任务仍只需几分钟；不鼓励用满期限。家长设置的有效任务上限仍独立执行，见 [练习与休息](PRACTICE-LIMITS.md)。

总期限包括准备材料、看规则、反馈、主动暂停、切到后台和关闭页面后的时间。截止取总期限、内容有效期、下一家庭日三者中最早值，因此可能比表中时间短。开始前显示具体截止日期、时间和设备时区，不显示倒计时，也不因为阅读较慢而扣分。

询问只在说明、反馈、段落休息、普通暂停、题间空隙或新题呈现前出现。**正在答题或保存已接受操作时不插入询问**；限时题完整处理后再出现。自定节奏的搜索/记忆步骤也等待安全节点，原有效任务预算与总期限仍可结束过长练习。

页面有「今天到这里」和「我准备好了，继续」。前者作为正常的孩子主动结束保存，后者回到刚才的说明/反馈/休息位置，不跳过尚未读完的规则。选择继续后，下一次询问从此时重新间隔 4/5/6/6 分钟。没有作答/情绪字段，不保存或推断“累”“不专注”等标签，也不产生家长行为评分。

重开不会重新签发期限。询问状态仅留在当前页面内存，恢复时依据原签发时间重新判断；若已超过首次间隔，会再次询问。这是重新进入时的明确选择，不会改变任务成绩。普通暂停和切后台不能绕过已经出现的询问。

## 2. 签名与旧版兼容

第 2 版授权的签名正文增加：

```json
{
  "version": 2,
  "windowPolicy": {
    "version": "practice-window-1",
    "maxElapsedMs": 1200000,
    "checkInAfterMs": 240000
  }
}
```

这些字段与原来的会话、孩子、设备、传输、计划摘要、有效任务额度、事件上限及上传期限一起签名。客户端分别通过 Web Crypto / 原生验证器核验完整签名，再检查参数恰好对应计划年龄。未知版本、篡改、超过规则的截止时间或其他年龄的规则均拒绝准备。

历史第 1 版授权仍按原正文和期限核验，不补写新字段、不缩短原承诺。第 2 版仅在新建会话时签发；精确重试、重新登录、同设备恢复与换设备旧记录补传都不延长授权。旧版客户端不能读取第 2 版授权，部署时须先更新并验收两端客户端，再停止旧 API 并启用新服务；不混用会签发不同规则的新旧 API，Web 须完成下载并关闭本站旧页面后重开。不得把旧客户端接入新服务后的材料错误解释为记录丢失。

数据库不新增列；原 `continuation_grant` JSON 保存签名完整快照。家长导出中的公开 `authorization` 新增 `version` 与 `windowPolicy`，保留原期限字段，不输出设备标识或私钥。没有独立的休息选择/情绪记录。

难度判断只读取相同 windowPolicy 的历史，新规则不继承旧规则的升级证据；新条件从等级 1 开始。家长周回顾规则升级为 `weekly-descriptive-2`，将旧规则与新规则分组，并在详情说明总期限和询问间隔。未知/不匹配的规则记为条件不一致，抑制差值。计划、任务计分与原有历史结果不改写。

## 3. 计时与可靠保存

复用 `ContinuationClock`：单调时间与墙钟取保守值，保留最高时间和时钟异常检查点。新增 `elapsed()` 始终以原签发时间为起点，不以当前页面的创建时间为起点。后台冻结后恢复也检查截止，普通系统回拨会阻止继续。它不是可信硬件时钟，不能证明离线事件发生的物理时间。

到期时客户端先关闭输入窗口、停止音频和新题，再等待已接受的写入结束。随后只追加中断/结束事件；完整正式步骤已经结束时可保存完成元数据，否则结束原因是 `time_limit`。未完成的步骤不伪造正确或错误结果。仅停留说明页的到期记录可有 0 有效任务时间，不推进课程。

已记录事件沿用 7 天内的补传期限、原设备权限、服务端回放及幂等确认；过了录制期限不代表抹掉记录。服务器仍允许可信客户端补传此前记录的事件，不能仅凭客户端时间验证事件的真实发生时刻。

离线重开过期授权仍被拒绝；已有日志保留，联网后可通过原恢复/结束流程处理。首次准备材料期间若已过期，Web 会跳过新增离线准备并进入原有结束保存流程，不因准备离线包的断言将练习锁死。授权被替换、采集停止、内容召回和存储故障仍优先执行各自保护。

## 4. 两端交互实现

`packages/session-runtime/practice-window.ts` 提供规则、`PracticeCheckIn` 和双语文案；Web `Play.tsx`、原生 `Practice.tsx` 共用该逻辑。询问前同时检查页面阶段、活动题窗口、待写入数量和已回放状态，避免慢存储或旧回调重新展示题目。页面退出和授权失效沿用现有清理流程。

Web 询问标题可获程序焦点，两个选择都是正常按钮；原生提供标题语义与辅助功能播报。没有自动播放新声音、遮挡限时目标的弹窗或闪烁倒计时。实际屏幕阅读器、手机宽度和原生设备体验仍待验收。

内容工作台的候选试玩没有家庭签名授权，本批不强加家庭期限或询问，原试玩身份/期限与完整回执规则保留。后续把该规则纳入正式方法审核时，需再决定候选审核是否增加对应演练。

## 5. 验收和发布边界

自动检查覆盖四年龄签名与两端验证、较短内容/家庭日期期限、重试不续期、篡改/未知规则拒绝、历史第 1 版兼容、安全间隙、重复选择、后台/重开/回拨、慢保存和说明页零用时结束。HTTP 验证新授权正文和重启，完整 PostgreSQL 回归继续执行。实际页面结果见 [本批验收](qa/practice-window-v0.22.md)。

当前总期限只限制一份练习，不是家庭全部页面或设备级每日屏幕时间。结束后再开新练习会取得新的总期限，但原有效任务日额度不会重置。跨会话强制休息、总停留日额度、可信设备时间、疲劳研究及分龄参数审核仍未完成；本批不能表述为完整健康使用系统已验收。正式发布门槛保持关闭。

后续 v0.46 的开始前选择页会读取服务端当天练习安排：已有确认用时时提醒孩子可以先离开屏幕；暂停、尚有未确认练习或可用任务时间不足 5 秒时不再提供开始按钮，并可直接查看安排。这只是跨会话信息提示，不计量页面总停留，也没有新增强制休息参数；服务端在实际创建时仍重新校验当天额度。
