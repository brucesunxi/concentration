## 1. 组织与责任

建议投入 **12 个全职等效岗位**。已有完整研发团队时优先映射现有人员；以下工作量不能默认为都需要新增招聘。科学、统计、法务和母语内容质量不能由研发自动代替。

| 职能 | 全职等效 | 主要责任与最终负责内容 |
|---|---:|---|
| 产品负责人 | 1 | 用户范围、需求取舍、指标、商业方案、跨专业决策 |
| 科学/儿童发展负责人 | 1 | 任务协议、儿童使用边界、研究方案、不适事件评估 |
| 体验设计与用户研究 | 1 | 年龄分层、家庭流程、可访问性、试用观察 |
| Web 前端 | 2 | 家长端、网页练习、事件记录、离线、报告 |
| 移动端 | 2 | iOS/Android、音频缓存、权限、商店支付与设备质量 |
| 后端 | 2 | 身份、家庭权限、区域政策、会话、同步、支付 |
| 测试 | 1 | 跨端状态、协议、权限、同步与回归体系 |
| 平台/安全 | 1 | 部署、区域隔离、监控、供应链、备份、事件响应 |
| 内容与本地化制作 | 1 | 语音、图像、内容包、版本和母语审核协调 |
| 合计 | 12 | 外部专业支持另列预算 |

外部或共享岗位：统计人员、各市场隐私与产品法务、伦理/研究机构、母语审稿和译者、独立渗透测试、招募与家长客服。上线前明确客服语言、营业时段、升级渠道和账务权限。

每个内容版本须科学负责人和内容审核人批准；每个国家开放由产品、法务和安全共同签署；技术负责人对发布可靠性负责。研究结论由研究负责人和统计人员确认，不能由增长负责人改写为夸大效果。

### 2.1 关键依赖链

目标市场与年龄政策 → 同意/账号模型 → 数据采集与删除 → 任务协议冻结 → 有效试次记录 → 可比较报告 → 可行性研究 → 效果研究与可支持的表述。

语音与图像制作可与基础平台并行，但须依赖稳定文案 ID 和任务协议。支付开发可并行，开放销售须等待隐私、渠道与消费者流程完成。

## 3. 每个发布门槛的验收表

以下是候选内部目标，G0 时由团队承诺；没有达到时应缩小发布范围或修复，不为赶排期更换统计口径。

| 门槛 | 核心验收 | 负责人 |
|---|---|---|
| G0 | 首发经营主体/国家明确；内容适龄审查路径；用途与法规分类备忘录；主要研究指标与预算；数据保护影响评估初稿 | 产品 + 科学 + 法务 |
| G1 | 同一批事件可重算出一致结果；跨家庭访问被拒；一次完整撤回/删除演练；播放失败/断网不制造错误得分 | 技术 + 测试 + 安全 |
| G2 | 每个拟开放年龄/语言分层观察独立理解情况；目标 ≥85% 经一次演示可完成理解检查；无未关闭严重不适或权限缺陷 | 设计 + 科学 |
| G3 | 试用中有效事件完整率 ≥99%；至少 70% 家庭完成其约定练习次数的 60%；同时报告失访、负担和不适；不把留存当疗效 | 产品 + 研究 + 数据 |
| G4 | 关键安全缺陷为零、主要阻断缺陷为零；通过地区清单、同意、删除、支付、备份和客服演练；所有发布素材审核完成 | 技术 + 安全 + 法务 + 运营 |

小样本达到 85% 不意味着人群真实理解率已被精确估计，需报告人数和区间。若某分层未达标，仅暂停该分层。严重/疑似相关不适或数据泄露立即单独响应，不等待汇总指标触线。

## 5. 前两轮迭代：从明天可以开始

### Sprint 1：W1–2，确定边界并做真实技术验证

- 产品：映射 12 个岗位；确定候选市场与经营主体；建立决定记录、风险清单和需求看板。
- 科学：把原有搜索、抑制、记忆任务写成规范；确定首个主要研究人群与主要结果候选。
- 设计：访谈家长及两档青少年；完成家庭开户、儿童愿意参与、退出和共享的可点击流程。
- 研发：盘点现有规则与素材；用一个搜索任务验证纯引擎、可注入计时与事件回放；不先重写全部页面。
- 内容：核对 16 段语音，修订顺序播报和错误反馈需求；建立文案 ID、语音、字幕对应表。
- 安全/法务：画出真实供应商数据流；评估监护同意供应商、市场分类、区域身份服务与密钥处理。

演示材料：一份协议、一条完整的年龄/地区政策记录、一个可回放任务、家长/孩子全流程原型、已标记缺口的语音清单。Sprint 1 不以漂亮首页作为唯一完成标准。

### Sprint 2：W3–4，冻结接口并走通风险最大的路径

- 前后端共同冻结核心 API、事件契约、idempotency 与错误码；依据接口草案补齐身份与隐私接口。
- 建立家庭 A/B、两个孩子、照护人的测试数据，证明对象级授权有效。
- 做一次「开始 → 离线 → 中断 → 恢复 → 补传 → 重算 → 删除 → 再次补传被拒」的最小演示。
- 移动团队用真实设备验证音频取消、触控事件、后台恢复与离线存储；记录与 Web 的差异。
- 确定自适应样本窗口与仿真用例，明确什么情况下保持难度。
- 研究负责人完成主要指标、招募路线、样本量计算计划和伦理路径；产品完成付费访谈脚本。

Sprint 2 结束验收：G0 决议、核心契约 v0.1、威胁模型、两语言第一批审稿文案、未来四轮迭代的依赖与工时。未解决的法域或年龄组合保持关闭，不靠备注绕过。

## 7. 风险登记与处理

| 风险 | 触发信号 | 应对 | 负责人 |
|---|---|---|---|
| 游戏进步无法迁移 | 对照研究主要结果无差异 | 公开限制，收缩效果表述，检验生活支持部分；不改用好看的次要结果宣传 | 科学/产品 |
| 跨年龄不适配 | 某年龄层理解低、退出高、觉得幼稚 | 停该分层，重做交互与内容；不靠加长指导硬推 | 设计 |
| 亲子冲突或不适 | 家长反馈强迫练习、孩子反复拒绝 | 调整目标和反馈，提供停止，审查通知与报告 | 科学/运营 |
| 分类与渠道不确定 | 某市场需要额外许可或训练计划冲突 | 关闭对应市场，完成分类和资质路径后再开放 | 法务/产品 |
| 数据越权/泄漏 | 权限测试失败、异常导出、密钥暴露 | 停相关通道、轮换、调查、按法域响应；修复后复验 | 安全 |
| 内容或音频不一致 | 指令与判分不同、动态词序错 | 召回内容版本，修复测试与制作流程 | 内容/测试 |
| 离线记录失真 | 重复成绩、删除后回传、设备合并错 | 停合并策略，按事件回放修复；告知受影响家庭 | 后端 |
| 收入不足以支持服务 | 退款高、获客回收期长于留存 | 改包装与成本，缩市场；不通过延长孩子使用拉收入 | 产品/经营 |
| 正式研究超时 | 招募/伦理延迟或样本不足 | 保留有限练习产品表述，延后效果声明和扩龄 | 研究 |

## 8. 上线完成的定义

一个发布组合完成，不是「能打开网页」。必须同时满足：

1. 对应年龄与语言的协议、图片、语音、生活活动已审核，真实家庭可理解。
2. 数据权限、同意、撤回、跨设备、导出与删除都有实际测试证据。
3. 支付、取消、退款、客服和恢复流程可运行，家长知道买到什么。
4. 技术指标通过参考设备和生产演练，发现故障能停止新会话并恢复。
5. 营销文案逐条对应证据；未做研究的效果不写，未批准国家不开放销售。
6. 负责人签署发布记录，包含版本、范围、已知限制、监测指标与回退方案。

第一项实施动作：确定负责人后，从 E-01 + D-01 + A-01 的最小纵向闭环开始，同时由科学负责人完成 S-01，内容负责人修正语音与实际任务不一致的问题。
