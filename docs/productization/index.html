专注力家庭产品：产品化方案与技术设计

结论

本轮工程交接见 v0.29 原生声音与安全存储验收；完整语音制作范围见 语音缺口清单。前批生活目标见 家庭生活目标，练习与观察历史见 家庭历史翻页；面向产品和团队的原方案继续作为目标基线。

已补交包含声音降级和安全存储重试的 v0.29 本地测试包。iOS 模拟器包已安装并显示重试页面，系统诊断指出其 Keychain 权限缺失；Android APK 已签名核验但未安装。实际加密、登录、声音和设备流程仍未验收。

以当前三个小游戏为实验起点，建立面向全球家庭的「注意相关技能练习 + 生活中的策略实践 + 家长支持」产品。目标年龄暂定 6–17 岁，按 6–8、9–11、12–14、15–17 岁分别设计；用户是家庭家长和孩子，不以学校、机构管理系统为主线。

产品真正需要加深的是：任务协议是否可靠、孩子是否理解、能否把策略带进生活、家长能否提供合适的支持，以及是否有证据说明产品带来了变化。增加关卡、延长使用时间、生成更多报告，都不能单独回答这些问题。

本次设计的七项决定

  1. 全球架构，分市场发布。 英语、简体中文先做内容验证；国家、年龄、语言、任务版本分别设开放条件，翻译完成不等于可以上市。
  2. 儿童与青少年两套体验。 共享任务引擎与家庭账号，但故事、美术、语言、目标和家长共享方式不同。6 岁以下作为独立研究方向，不向下直接套用。
  3. 训练与生活实践相连接。 每次练习只教一个可执行策略，结束后安排一个短小的现实任务；不把游戏分数包装为「专注力指数」。
  4. 语音仍使用预生成素材。 延续已认可的 Azure 中文音色，制作与校对固定语音包；运行时播放文件，不接实时大模型，不上传儿童语音。
  5. 完整团队并行建设。 建议约 12 个全职等效岗位，以 32 周为有限市场发布目标；效果研究另有完整观察周期，不能以版本上线代替。
  6. 先建立可信的基础能力。 首批四类任务、家庭账号、监护人同意、可靠记录、跨设备恢复、家长周报、内容发布系统与支付闭环优先。
  7. 效果按证据逐步表述。 上市初期提供适龄练习和家庭支持，不宣称治疗 ADHD、提高智商或保证学习成绩。任何效果主张须限定到经过研究的版本、人群和结果。

用户已确认面向全球家庭，且已有完整研发团队。下述约 12 个全职等效岗位是能力和工时分配参考；执行时把负责人映射到现有团队，不以重新组建团队为前提。6–17 岁是当前建议的首期覆盖范围，各年龄和市场仍分别验收。

02 / 产品方案

设计版本 1.0 / 2026-09-30。所有课程时长、难度阈值、价格与经营目标均为待验证的设计假设，不能引用为已证实的效果。

1. 定位与价值

1.1 要解决的实际问题

家庭通常看到的是「开始作业很困难」「做两步就忘了下一步」「急着点、急着回答」「遇到干扰后回不来」。这些表现可能受到睡眠、情绪、任务难度、感官条件、环境或发展差异影响。产品不能仅凭游戏表现判断原因。

产品的承诺是：提供结构清楚、时间有限的练习，帮助孩子尝试具体策略，帮助家长观察同类生活任务中的变化。核心价值链为：理解规则 → 尝试策略 → 完成适度挑战 → 在生活中尝试 → 一起回顾。

购买者是家长；真正使用者包含儿童和青少年。家长需要透明的方法、可控的花费、可解释的进展；孩子需要自主、胜任感和尊重。产品设计必须同时满足双方，不能把孩子变成家长监控面板中的分数。

1.2 可表达与暂不可表达的价值

允许的初期表达 需要产品自身证据后才能表达
提供视觉查找、等待反应、顺序记忆等练习 能改善某个年龄段日常注意表现，需明确研究条件与效果大小
提供循序渐进的任务和家长活动建议 比其他产品更有效，需直接比较或有充分依据
记录自己在相同任务条件下的表现 改善学习成绩、治疗 ADHD、替代专业支持
用短时练习学习具体策略 某分数代表注意力年龄、智商或临床风险

5. 家庭体验与信息架构

5.1 家长端

首页显示本周约定、下一次建议、孩子选择的生活目标和「需要帮助」入口。报告分为三张卡：练过什么策略、同条件任务里发生了什么、生活记录有没有变化。

每张趋势卡必须标注任务版本、有效次数、是否使用提示、可比较条件和数据缺口。样本不足显示「还需要几次相同条件的练习」，不画平滑的能力增长曲线。家长可看账单、调整提醒、导出/删除数据、管理照护人；这些权限不能等同。

5.2 儿童与青少年端

儿童端只显示本次目标、操作区域、帮助和结束按钮。青少年端允许选择目标、查看自己的策略记录，并清楚知道哪些信息会与家长共享。初期不采集自由文本日记、情绪隐私日志或私聊内容，减少不必要的敏感信息。

共享分层：基础使用状态与家庭约定；可选的策略回顾；原始事件仅在合法必要、权限明确的导出或研究流程中处理。青少年自评默认不作为家长绩效看板；当地法律涉及监护人访问或数据主体权利时，由政策与支持流程处理，不能承诺绝对秘密。

共享范围改变前，用孩子能读懂的话展示。例如：「爸爸现在能看到这周练了哪些策略和你愿意分享的目标。」涉及适用法定同意年龄或成年转换时重新确认权限。家长分离、监护争议、邀请撤销设人工处理入口，不让付款者天然获得全部儿童数据。

本地 v0.16 已实现逐次结构化回顾分享：默认不保存答案，明确分享后家长可见，可撤回目标与历史中的答案。它是上述分层的一部分；独立身份、逐成员权限、地区访问权和成年转换仍待实施。见 自主分享设计。

6.2 可行性研究建议

首轮 32–48 个家庭开展可用性研究，四个年龄段均覆盖英语与简体中文，纳入不同设备、阅读能力与家庭结构；每个分层仍是少量样本，只用于发现问题。后续 80–120 个家庭开展 8 周可行性研究，观察练习完成、生活实践、挫败或不适、退出原因和数据缺失，不作疗效宣称。

正式效果研究先选一个明确人群，例如「英语地区 6–11 岁、家长报告日常注意困难、符合明确纳排标准的家庭」。是否纳入已有 ADHD 诊断、是否保持其他支持不变，由研究负责人和伦理审查决定；分层随机并记录共同干预，不能混入后再作未经计划的比较。

6.3 正式研究的执行要求

  • 主要结果只选一个，优先与家庭日常功能有关的、年龄与语言适用的有效工具；在招募前完成授权、量表选择与统计分析计划。具体量表由研究负责人在第 4 周定稿。
  • 次要结果包含未训练材料任务、策略使用、孩子可接受性和家长负担；训练游戏分数作为机制/过程结果，不代替主要结果。
  • 使用时长、关注程度、期待与视觉吸引力尽量匹配的主动对照。用户不能完全盲法时承认这一限制；独立评估者与统计分析按可能范围设盲。
  • T0 起始、T1 第 8 周、T2 结束后 4 周；平行材料减小重测熟悉效应，固定协议不随自适应难度变动。
  • 按随机分组分析，预先处理缺失与多重比较；给出效应量和置信区间，同时报告负面或无差异结果。
  • 未成年人参与需适用的监护人同意和本人愿意参与；研究同意单独取得，退出研究不能失去已购买的基础服务。
  • 记录不适、亲子冲突、反复受挫与过度使用。严重或疑似与产品有关的事件立即暂停对应流程并由负责人评估；不等待样本量达标。

样本量不能凭经验定成 30 人。仅作预算示例：双侧 α=0.05、80% 把握度、标准化差异 d=0.35，简单独立两组近似约 128 人/组；若预计 20% 失访，总招募约 320 人。基线调整、主要量表、家庭内相关性、多个年龄/语言分层都会改变结果，正式数字须统计人员计算。不能用这 320 人同时证明四个年龄段、所有国家和两种语言都有效。

7. 国际化与市场进入

7.1 发布单元

发布单元是 国家/地区 × 年龄段 × 语言 × 内容协议 × 客户端渠道。后台只有这组组合全部通过评审，才可开户与发放训练计划。语言选择不改变数据区域和监护政策；修改居住国家需要重新评估与迁移流程。

8. 商业模式与运营

8.1 收费结构

建议家庭付费，默认一个家庭最多 3 个儿童档案；先验证 8 周课程包和家庭订阅两种方案，避免无限使用成为卖点。免费体验包含完整的规则说明、数次练习与生活活动，家长能在购买前理解产品。

价格仅作访谈锚点：月付 9.99–14.99 美元、年付 69–99 美元，或 8 周课程包 19–29 美元；不是定价结论，年付价格与支持成本须用真实留存重新计算。各地区按购买力、税、退款与渠道费定价，不机械汇率换算。

所有支付、续费、取消和外链由成人完成；儿童界面没有促销倒计时、广告、抽奖或劝说购买。到期不阻断导出、删除与已形成记录的访问。研究参与与付费分离。

8.2 单位经济测算

以已扣税退款但未扣渠道费的家庭月收入 10 美元举例，假设渠道成本 15%、每家庭月可变成本 1.5 美元，则贡献毛利约 7 美元。获客成本 40 美元对应约 5.7 个付费月才能回收，尚未覆盖固定研发与研究成本。这里的 15% 只是模型输入，不是任一商店的确定费率；不同渠道需单独重算。没有真实付费留存时不公布长期价值或盈利结论。

8.3 首批获客与服务

先做 20–30 个分市场的家长定价访谈和青少年体验访谈，再用经审核的方法介绍、家庭活动内容和家长社区开展小范围招募。邀请家庭自愿推荐，不要求儿童传播个人成绩，不把诊断标签用于广告定向。

3. 任务引擎与计时

3.1 状态机

所有状态都允许退出到 Aborted；受权限撤回、内容召回或数据删除影响时进入 Revoked。Aborted 保留有效的已完成块，Revoked 不继续上传训练事件。计时任务不可通过关闭退出按钮强行完成。

3.2 计时与有效性规则

  • 使用单调时钟记录试次内相对时间；服务端时间用于接收与账务，不替代客户端反应时。墙上时钟仅作课程日期参考。
  • 页面布局和素材就绪后，在确认绘制的时点记录视觉 onset；听觉任务在音频实际播放回调记录 onset。音频资源下载开始不能算刺激出现。
  • 屏幕刷新、触控输入、蓝牙音频延迟、设备负载都会影响测量；设备模式与渲染/音频异常随试次记录。不得宣传毫秒级临床精度或直接跨设备比较。
  • 前后台切换、系统打断、资源失败、明显帧异常时，将该试次标记 interrupted 或 technical_invalid；不作为漏反应，不进入难度计算。
  • 同一试次仅接受协议允许的输入；重复点击按原始输入保留并由评分器处理，不能简单在客户端丢弃后声称没有冲动误触。
  • 练习、正式练习、固定测量分别标记 mode。提示后形成 assisted 试次，允许继续，不混入首次独立表现。
  • 正式测量固定时序、种子策略与参数，训练自适应不可修改测量协议。

随机算法与种子版本固定；服务端发放计划种子及内容版本，可重建目标序列。客户端事件记录呈现结果、输入与异常，服务端重算得分。此机制能发现程序错误或不一致，不能证明实际操作人就是孩子，也不能阻止所有客户端伪造。

6. API、离线与同步

核心机器可读草案见 OpenAPI。以下规则对 Web 与原生一致。

6.1 会话事务

  1. 创建会话：验证地区/年龄/同意/成员关系/权益/内容发布状态，用 Idempotency-Key 请求。服务端返回 session_id、计划种子、冻结的版本、离线授权到期时间与事件限制。
  2. 本地逐事件落盘，再向界面显示「已在此设备保存」。建议每完成试次写一次事务；事件上传可按块或最多 100 条/256 KiB 批量发送。
  3. 同步事件：服务端先验权，再校验版本、类型、会话归属和序号；重复 ID 且规范化内容一致返回已接收；同 ID 不同内容返回冲突，禁止覆盖。
  4. 结束提交：客户端提交最后序号 last_seq 和完成原因。服务端确认 1..last_seq 连续、必需事件完整后重算；缺失返回 409 和范围，客户端补传后重试。明确零事件放弃的请求独立处理。
  5. 结果页本地可以先展示标注为「待同步」的结果；只有服务端确认的版本进入跨设备周报。结束重复提交得到同一结果，不二次累计。

seq 是传输完整性依据，不是可信墙上时间。服务端接受乱序到达但不接受重复序号不同事件；不允许客户端直接上传「得分 95」作为事实。删除/撤销检查优先于幂等重放，旧请求不能复活已删除档案。

6.2 离线授权与冲突

  • 下载的公共训练内容可长期缓存，私人事件放 IndexedDB/原生加密存储；缓存可能被系统清理，应明确尚未同步的数据风险。浏览器存储配额与清理
  • 首版仅允许已在线授权的会话在限定窗口离线继续，授权最长 24 小时且受预计时长约束；无有效授权时可进入不记录个人数据的公共示范，不自行创建计入课程的新会话。
  • 离线令牌不含姓名等资料，签名并绑定档案、设备、版本和范围。离线无法即时感知撤销，界面如实说明；联网先检查撤销/删除，再处理 outbox。不得承诺能即时擦除永不联网的设备。
  • 为避免两台设备重复推进，一名孩子只允许一个有效训练租约；第二台可只读进度或确认接管，接管会使旧会话失去计入计划资格。旧设备数据仅在仍有合法处理依据时进入带来源的练习记录，不合并伪装成连续一次。
  • 自适应状态、课程单元采用服务器版本号与 compare-and-swap；过期客户端不能覆盖新决定。用户目标、共享范围更新用 If-Match，冲突时显示两份选择，由成人/有权用户确认。
  • Service Worker 仅缓存公开静态资源，不缓存私人 API 响应；退出家庭、切换档案、成员撤销和删除时清理对应本地命名空间。活跃试次中不强行升级 Service Worker。
  • 超过 7 天的未同步事件按已告知策略清理；到期前提醒家长设备有未同步记录。失去同意后的事件不继续收集；必要的删除状态查询与用户权利处理须有独立合法依据。

7. 内容、图片与语音生产线

7.1 内容发布

流程：任务协议 → 文案 → 适龄/跨文化审稿 → 素材制作 → 自动检查 → 人工试听/试玩 → 双人批准 → 签名不可变包 → 灰度 → 监控与召回。

内容包含 task_version、policy_version、locale、年龄范围、刺激定义、随机化、参数上下限、字幕、音频映射、生活活动、资源校验值与审核记录。发布人不能同时是唯一批准人。示例见 内容包草案。

客户端只解释受限数据，不从内容包执行 JavaScript。策略参数超界、签名不符、依赖不兼容或未批准区域时拒绝加载。会话锁定包版本；正常更新在下一会话生效，安全召回则暂停并解释。

7.2 语音

延续 zh-CN-XiaoxiaoNeural 作为中文候选主音色，保留现有用户认可的试听样本作参考。语音生成在受控制作环境一次完成；运行时只播放素材。生产工具的密钥保存在密钥管理服务，浏览器、Git、构建产物和日志不包含密钥；既往在聊天或其他非密钥系统出现的凭据应进入轮换清单。

不把孩子姓名、表现、家长自由文本传给 TTS。英语及其他语言选音色后由母语审稿人试听，不把翻译文本批量生成成功当成可用。云 TTS 只发送固定文案，供应商合同与其他业务数据流仍需单独评估。Azure 文本转语音接口

播放器仅有一个活动通道，支持 prepare/play/stop/replay/fail 状态，使用 generation token 丢弃过期回调。点击重播、换页、暂停时同步清理队列与 busy；播放失败只触发一次回退。听觉测量模式播放失败即标无效；普通引导可用字幕继续。系统 TTS 仅作家长明确选择的便利功能，声音来源与可能联网情况需说明，不作为正式测量的默认回退。

7.3 图片与本地化

图像资产必须有源文件、授权与生成记录、尺寸、透明区域、锚点、碰撞区、缩略图和低带宽版本。训练刺激优先保证边缘清晰、亮度/大小可控，装饰性的精致程度不能使目标比干扰物天然更显眼。

四套年龄内容至少各有一套完整示范、正式刺激与生活活动。英语和中文使用 ICU 消息、复数/长度测试、字体覆盖；RTL 布局预留但未审稿前不宣称支持。刺激左右顺序在 RTL 语言下是否镜像，属于协议决定，不能由 CSS 自动改变。

媒体预算假设：首屏压缩资源 ≤1.5 MB，首个离线训练包 ≤20 MB，后续按需下载；以真实中低端 Android/iPad、弱网、静音、蓝牙与大字号检查。下载进度和重试清楚可见。

8. 隐私、安全与数据生命周期

8.1 最小采集

不默认采集精确位置、摄像头、麦克风、广告 ID、学校或诊断资料。年龄以满足适龄与法律判断所需的最小信息收集；生日临界需要确认时使用专门流程。诊断等研究资料放独立受控系统，不作为商业推荐标签。

可验证监护同意是目的与法域相关的业务流程，不能只用勾选框。优先使用适用的验证供应商，保存方法、交易引用与结果，避免自己储存身份证件。营销同意、研究同意与提供核心服务所需处理分别管理，不以拒绝营销阻止孩子练习。

删除事务：冻结新写入 → 撤销令牌/会话/共享链接 → 建立最小删除标记 → 清理数据库、对象、队列、缓存、报表及供应商副本 → 标记备份到期与恢复过滤 → 生成可审计结果。删除标记也要限定字段与保留目的。

9. 支付与权益

以家庭为权益主体，采用渠道适配器支持 Web、App Store、Google Play 及批准市场的支付渠道。客户端支付回执需服务端验证，回调按 provider_event_id 去重，状态机处理 active、grace、expired、refunded。取消自动续费不等于已付周期立即失效；退款和账务调整以渠道与当地规则为准。

允许网络故障时在签名权益宽限窗口内完成已授权练习，绝不因支付通知延迟中断正在进行的一题。付款入口、价格、续费与取消都在成人区。不得把某一家支付渠道的费率或全球覆盖写死为商业前提。

10. 运维、容量与质量门槛

10.1 初期容量假设

假设 10,000 周活跃孩子，每周 3 次、每次 100 个事件，即每周 300 万事件。按每事件 1 KB 粗算约 3 GB 原始载荷/周，尚未计索引、复制和备份。10,000 次各 20 MB 的首次包下载约 200 GB。该估算用于容量压测与成本模型，不是用户增长预测。

初期验证 500 并发练习、事件批量上传峰值与报告任务同时运行；根据实际每试次事件数重算容量。游戏运行不依赖逐次网络往返，CDN 故障和 API 故障分别降级。

10.4 发布与回滚

内部成人 → 指定家庭 → 某一市场/年龄/语言的小比例 → 扩大。远程开关只能控制已编译能力和经过模式校验的参数。每个版本有 kill switch，能停止特定内容/地区的新会话而保留导出、取消与删除功能。

数据库采用先兼容旧读写再清理的迁移方式。客户端至少支持约定的前两版内容契约；太旧时提供清楚升级路径，不能丢弃未同步数据。研究队列固定内容和策略；安全修复单独记录偏离协议，不在研究中静默改变难度。

  • 研发：盘点现有规则与素材；用一个搜索任务验证纯引擎、可注入计时与事件回放；不先重写全部页面。
  • 内容：核对 16 段语音，修订顺序播报和错误反馈需求；建立文案 ID、语音、字幕对应表。
  • 安全/法务：画出真实供应商数据流；评估监护同意供应商、市场分类、区域身份服务与密钥处理。

演示材料：一份协议、一条完整的年龄/地区政策记录、一个可回放任务、家长/孩子全流程原型、已标记缺口的语音清单。Sprint 1 不以漂亮首页作为唯一完成标准。

Sprint 2：W3–4，冻结接口并走通风险最大的路径

  • 前后端共同冻结核心 API、事件契约、idempotency 与错误码；依据接口草案补齐身份与隐私接口。
  • 建立家庭 A/B、两个孩子、照护人的测试数据，证明对象级授权有效。
  • 做一次「开始 → 离线 → 中断 → 恢复 → 补传 → 重算 → 删除 → 再次补传被拒」的最小演示。
  • 移动团队用真实设备验证音频取消、触控事件、后台恢复与离线存储；记录与 Web 的差异。
  • 确定自适应样本窗口与仿真用例，明确什么情况下保持难度。
  • 研究负责人完成主要指标、招募路线、样本量计算计划和伦理路径；产品完成付费访谈脚本。

Sprint 2 结束验收：G0 决议、核心契约 v0.1、威胁模型、两语言第一批审稿文案、未来四轮迭代的依赖与工时。未解决的法域或年龄组合保持关闭，不靠备注绕过。

8. 上线完成的定义

一个发布组合完成，不是「能打开网页」。必须同时满足：

  1. 对应年龄与语言的协议、图片、语音、生活活动已审核，真实家庭可理解。
  2. 数据权限、同意、撤回、跨设备、导出与删除都有实际测试证据。
  3. 支付、取消、退款、客服和恢复流程可运行，家长知道买到什么。
  4. 技术指标通过参考设备和生产演练，发现故障能停止新会话并恢复。
  5. 营销文案逐条对应证据；未做研究的效果不写，未批准国家不开放销售。
  6. 负责人签署发布记录，包含版本、范围、已知限制、监测指标与回退方案。

第一项实施动作：确定负责人后，从 E-01 + D-01 + A-01 的最小纵向闭环开始，同时由科学负责人完成 S-01，内容负责人修正语音与实际任务不一致的问题。
