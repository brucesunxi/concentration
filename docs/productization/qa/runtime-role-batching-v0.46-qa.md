# Neon 启动权限核验往返优化

2026-10-06。目标是缩短 Vercel 冷启动期间的数据库权限核验，不移除运行账号安全门槛。未修改 schema、授权角色或生产数据。

## 改动与保留的门槛

运行账号仍先核查危险角色继承、迁移表读取权限和 schema 32。随后在同一事务的一次参数化目录查询中读取家庭表与账本行级隔离、预期策略数量、建表权限、跨角色权限、只读内容和账本权限、危险表权限、迁移写权限、必需函数权限、限流表直接权限及运行表必要授权。失败仍使用原有拒绝码；已存在的只读审计事务保持原边界。

## 验证

- PGlite 限权角色在一次外层事务中完成 4 次查询；撤销账本读取授权仍返回 `DATABASE_BILLING_READ_REQUIRED`。
- 分别关闭 `children` 的行级安全、向家庭角色授予工作台表读取权限和撤销必需函数执行权限，启动核验分别拒绝；恢复后通过。工作台受限角色也单独通过，额外授予家庭 `children` 表读取权限后同样被拒绝。
- 使用现有 Neon `focus_family_runtime` 账号，在经验证的 TLS 连接与 `BEGIN READ ONLY` 中各运行 3 次相同核验。改动前核验用时 **4655、4737、4613 毫秒**；改动后为 **1068、1124、1128 毫秒**。这些是从本机到 Neon 的目录检查耗时，包含跨区域网络往返，不是用户端首屏时间或受控延迟基准。
- 两组运行均返回 schema 32、隔离验证通过，未查询家庭行、未写入数据。云端检查和 Vercel 实际启动耗时将在本批提交时核对。

本机最终回归：**377/377** 项业务测试、**19/19** 项 HTTP 测试及 TypeScript/公开秘密扫描通过。云端检查与 Vercel 运行数据仍须按本批提交复核。

## 仍需完成

正式发布仍须独立 Neon 测试分支上的并发、连接耗尽、故障及备份恢复演练。一次成功的权限目录查询不能证明这些运行条件或真实地区准入。
