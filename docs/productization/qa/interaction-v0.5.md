# v0.5 练习计时与中断修复

日期：2026-09-30。平台 0.5.0，原生开发壳 0.2.0。承接 [家长资料管理与双平台验收](parent-data-v0.5.md)，本轮修改 Web、原生练习页面及共享运行器，没有改动原生依赖。

## 修复的问题

### 1. 慢存储缩短可操作窗口

原实现等待 IndexedDB / SQLCipher 写入 `present` 后才开放输入，但事件中的开始时间取自写入之前。限时任务因此可能出现：目标已开始计时，按钮仍不可用；延迟越大，孩子真正可操作的时间越短。

现在用 `TrialLifecycle` 管理当前页面的响应窗口，与已经持久化的记录分开。呈现时记录窗口起点并开放限时按钮；点击在发生时取得时间，排在呈现事件之后保存，计时器不等待存储。结束窗口后立即隐藏目标并停止接受输入，再等待本步写入完成。

只有写入成功的事件才进入已保存状态与成绩回放。写入失败仍停止练习，不能把页面上已经出现的目标视为已保存记录。正在写入时界面显示「正在记录」。

Web 在准备绘制的阶段隐藏刺激并从可访问性树排除，避免事件计时之前提前看到目标。原生继续在准备阶段隐藏刺激。两端均保留当前 JS 相邻帧近似方法，**本次没有完成物理屏幕呈现或输入延迟校准**。

### 2. 同一批操作漏掉中断

原批处理按整批开始前的状态过滤 `interrupt`。在没有活动题时提交 `[present, interrupt]`，中断会被丢弃，界面却进入暂停；重做可能撞上仍活动的旧题。

两端现在使用同一个 `appendObservations`，按操作顺序回放。`present` 后的 `interrupt` 会记录；已经关闭的题目收到旧回调时，忽略不适用操作，仍能执行之后合法的 `end`。整批验证完成后才写入日志。

### 3. 暂停后的旧回调

每次呈现、暂停、结束和离开页面都更新交互版本。异步保存、帧观察和计时器只影响对应版本；重做同一个 trial id 也会取得新的交互版本。暂停立即关闭输入和画面，不再等待日志写入。保存中的暂停按钮仍可用。

从后台返回不会自动开始题目。准备材料期间进入后台，完成加载后也停留在暂停页。已结束会话不会再次进入呈现阶段。

### 4. 一次写入失败后禁止跳过缺口

原生运行器现在会锁住发生记录错误的队列，连已经排队的后续命令也不再写入。这样即使存储只短暂失败，也不能在丢失 `present` 后单独保存 `end`。需要重新打开练习，先从已经保存的完整前缀恢复。正常离开页面时，已接受且未出错的写入仍会完成。

## 本轮验证

| 证据 | 结果及实际覆盖 |
|---|---|
| 共享运行器检查 | 15 项通过；新增 6 项涉及同批呈现/中断、旧操作后结束、跨整个题目窗口的慢写入、保存中切后台、同一题重做后的旧计时器、短暂写入失败后拒绝跳过缺口 |
| 全部自动检查 | 87 / 87 通过 |
| 真实 HTTP | 3 / 3 通过；真实进程、临时数据库和重启，覆盖原生事件与家长资料流程 |
| Web 类型与构建 | 通过；JS 340.21 kB，gzip 106.56 kB |
| 原生类型检查 | 通过 |
| Hermes 导出 | iOS / Android 通过；约 2.7 / 2.8 MB |
| 实际界面与设备 | 未验证；本轮工具确认 Mac 仍锁屏 |

慢存储用例把日志写入阻塞到 9000 ms，但仍验证 100 ms 呈现、500 / 650 ms 两次响应、3705 ms 提交；回放得到首次响应 400 ms、两次响应和完整 3600 ms 窗口。该结果证明代码对观察时间的保留，不能证明设备的物理呈现精度。

原生工作区中的源码已同步到当前 Metro 所在的隔离目录。已有 Debug 壳加载新 JavaScript；本轮没有重新生成或重新安装 APK / iOS App，不能拿 Hermes 导出冒充新的原生编译证据。源码与导出文件摘要见 [运行代码证据](interaction-runtime-v0.5.json)，原生壳编译记录仍见 [双平台构建证据](native-build-v0.5.json)。

## 下一步验收

解锁后在 Web、iOS 与 Android 分别操作四任务，重点检查准备画面、慢写入期间点击/暂停、后台恢复、同一题连续重做、结束时限边界和辅助操作；同时检查字体放大与读屏。真实设备计时应独立测量，不以本轮自动检查代替。历史结果保持原始事件解释，本轮不会凭修复后的代码伪造旧记录中没有采集到的点击。
