## 新增反例与修复证据

### 跨端授权

HTTP 检查使用独立数据库、随机虚构家庭和本机端口，覆盖：

- Web 身份令牌不能在原生传输中使用，原生令牌不能冒充 Web Cookie。
- 原生请求带 Origin 或 Cookie 被拒；非原生请求带 Authorization 被拒。
- 原生进入练习时服务端撤销原家长会话，新凭据只能访问绑定孩子，不能查看家长报告。
- 原生与 Web 的任务平台条件匹配；原生合成 Go/No-Go 事件完成回放与提交，重启后结果保留。
- 原生退出撤销原生会话；不发送清除浏览器 Cookie 的副作用。

这些检查实际经过 HTTP，但没有执行手机上的 SecureStore，也没有验证真实触摸和系统生命周期。

### 持久化与恢复

- 四类原生计划实际记录、保存和重放输入；结果来自回放。
- 上传成功但确认丢失时重传相同事件；未确认记录不会提前删除。
- 本机写入失败不发布内存中的伪成功事件。
- 重启遗留活动题记录 reload 中断，不能把不可知的显示时间算入成绩。
- 离开页面后已接受的写入完成，后续输入被拒。
- 服务器回执不允许确认超出本次快照的记录。
- 服务器只有后续序号时，从缺失的连续前缀补传；Web 同步修复同类错误。
- 确认撤回时先等待已接受写入，再清除日志，不允许晚到保存重新生成日志。
- 搜索正式阶段连续三次错误进入暂停，计时题快速恢复仍保持最小间隔。

### 身份切换竞态

三个新增反例验证：写入儿童令牌时进入后台，必须先清除旧值再接受新身份；过期的家长登录不能删除当前凭据；安全存储失败后仍能再次执行明确退出。UI 身份版本检查避免晚到的开始练习、登录或退出回调覆盖新画面。测试使用可控的存储端口，真实 SecureStore 的行为仍在设备验收范围。

### 内容验证

原生适配器与 WebCrypto 对全部现有内容包和字节取得相同验证结果。测试覆盖 P-256 合法的两种 S 形式、错误公钥、被修改内容及现有审核规则，避免因签名格式或默认低 S 限制误拒正常发布包。

## 构建环境与可复现性

本机：Apple Silicon、Node 26.5.0、Xcode 26.6、iOS Simulator SDK 26.5、系统 Ruby 2.6.10。原生依赖按 npm 锁文件固定；CocoaPods 1.16.2、Bundler 2.4.22 及 Ruby 依赖锁文件随交接保留。

源码目录名含隐藏字符，RubyGems 对目标路径处理异常。构建改在只复制源码和已安装依赖的临时目录；没有复制家庭数据库、环境密钥或内容私钥。可通过 `npm run mobile:prepare-build` 复现源码准备。实际本批 iOS 构建目录为 `/private/tmp/focus-native-build-z4OuQt`，临时路径不是长期发布地址。

系统 Ruby 的 ActiveSupport 需要先在 Bundler 环境内加载 logger；预编译模块检测还遇到缺少 `filter_map`，工具回退到源码编译。团队 CI 应使用受维护 Ruby 并重新锁定验证，不把本机兼容操作当作生产工具链。首轮 Xcode 还受外部 GCC 设置影响，修复方式仅为当前构建显式指定 Apple Clang。最终构建成功，端口和权限声明也重新编译检查；未改变全局编译器设置。

本批 Expo 命令最初因 CLI 遥测试图写用户目录而失败，新增项目命令入口关闭遥测后打包成功。没有把首次失败隐藏为“所有命令一次通过”。

### 依赖审计

Vite 从 8.0.13 升级到 8.3.1，处理本批扫描发现的相关告警。剩余 10 个 moderate 为 Expo 构建工具链 `xcode → uuid 7.0.3` 的直接及级联项；不是 10 个独立业务漏洞。所查 `xcode` 源码调用 `uuid.v4()`，已知公告关注较旧 UUID 缓冲区 API，这只能说明当前调用面，不能据此把告警标为解决。[UUID 安全公告](https://github.com/advisories/GHSA-w5hq-g745-h8pq)

试验的 npm override 没有改变实际解析版本，已移除；未使用会回退到不兼容 Expo 主版本的强制修复。平台负责人仍须完成受支持升级或受审补丁、重新审计与回归测试。
