# v0.17 家庭网页版本发布验收

日期：2026-09-30 至 2026-10-01（本地时间）。平台 0.17.0，任务引擎 2.0.0，源内容 0.7.2-preview。原生应用仍为 0.2.0，本轮没有重新导出、打包或安装原生应用。

## 实际结果

新构建不再覆盖正在使用的家庭网页目录。检查通过后发布完整版本，保留旧哈希资源；已打开的旧首页在新版本发布后首次加载生活目标模块并保存成功。关闭旧页重开后进入新版本，登录和同一目标保留。这直接覆盖 v0.16 验收遇到的懒加载文件丢失问题。

HTTP 检查实际启动家庭 API；在保存虚构目标后发布第二个版本，同时发起 20 个首页读取，结果都为完整的第一或第二版 HTML。随后验证旧 JS 字节、HEAD、缓存头、安全头、私有路径拒绝、失败构建保持当前版，以及进程重启后原 Cookie、家庭与目标继续可读。静态 HTTP 夹具用于确定性检查，下面的浏览器流程另使用真实家庭界面。

编写期间修正了 Node 原生 TypeScript 执行不支持构造函数参数属性的问题；最终类型、执行与完整回归均通过。最终复查还修正了首次迁移中跨请求更新标记可能误报缺失的问题，增加并发迁移检查后重新完成回归；家庭构建字节未改变。没有通过跳过失败用例取得上述结果。

## 真实浏览器跨版本流程

环境为本机 4228 隔离服务，Codex 内置浏览器，虚构家庭 Update-QA-017 和 9–11 岁档案“版本验收小树”。没有输入真实儿童资料；没有接触外部部署、支付或语音服务。

1. 将既有 v0.16 构建作为初始版本，打开真实家庭首页并登录。此时未进入生活目标，避免预先缓存该页面造成假阳性。
2. 页面实际 DOM 的入口为 `/assets/index-BhqvSRpO.js`。
3. 发布真实 v0.17 构建。新入口为 `/assets/index-3Ex4CRgY.js`；生活目标代码由 `LifeGoals-CygoWtH-.js` 变为 `LifeGoals-Dwsiiwlr.js`，确实是不同文件名。
4. 保持旧页面不刷新，首次点击生活小目标。页面成功出现，DOM 中入口仍为旧文件；保存“做一张自己的步骤卡”成功。读取到的浏览器错误日志为空。
5. 让页面进行更新检查，再关闭该来源的测试页后重开。入口变为新文件，家长页面显示“网页版本 0.17.0”，家庭登录保留。
6. 再打开生活目标，原建议和总数 1 仍在，新页面错误日志为空。

没有通过浏览器隐藏状态或网络注入制造结果。入口版本读取来自 DOM 中的 script 标签，发布摘要来自独立的本机发布工具。没有声称新 Service Worker 在旧页面还活跃时强制生效。
